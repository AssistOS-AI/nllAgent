From retention standard to audited policy

This tutorial follows the actual product boundary: first compile the authority into an agent, then use that immutable build to analyze a separate policy. The business result is never written in LongTextJS and never requested from Codex.

1. Prepare the theory

The authority states that personal data may be kept for no more than five years after collection. A longer period is allowed only when a documented legal obligation applies to the same data and period. The authority also says absence can be used only after the complete exception register has been reviewed.

node bin/nllagent-train.mjs train \
  --agent privacy-retention \
  --theory agentsEval/privacy-retention/theory/retention-standard.md \
  --data-root /tmp/nll-environment

The host creates a TRAIN context. Codex uses the generated constructor and SDK catalogs rather than inventing data fields. The candidate is reviewed and promoted only if its actual tests and semantic benchmarks pass.

2. Inspect what was trained

node bin/nllagent.mjs agent inspect \
  --agent privacy-retention \
  --data-root /tmp/nll-environment

node tools/nll.mjs context inspect \
  /tmp/nll-environment/agents/privacy-retention/current/context/agent-context.mjs

The context lists the exact ontology, circuit tree, concepts and roles demanded from a document, exact scopes that can support absence, and reusable SDK providers. It is executable and has a digest; it is not a prompt assembled by convention.

3. Analyze a policy

node bin/nllagent-analyze.mjs analyze \
  --agent privacy-retention \
  --task customer-policy-review \
  --input agentsEval/privacy-retention/input/customer-policy.md \
  --output /tmp/customer-policy-report.md \
  --data-root /tmp/nll-environment

Before Codex reads the policy, the task pins the selected build and source digest. Codex receives only the ANALYZE context and writes a dependency-free materializer function. It identifies concrete retention claims, legal-obligation claims, policy sections, exact spans, and justified coverage. It does not emit VIOLATED.

4. Follow a real trace

For the ten-year customer-profile clause, the deterministic trace should contain this chain:

source span "ten years after collection"
  → explicit Retain claim in policy-retention scope
  → typed duration normalization
  → greater-than-five-years = TRUE
  → query LegalObligation for the same data and scope
  → zero matches + closed exception-register coverage
  → retention decision row = VIOLATED
  → finding with the retention and authority evidence

If the appendix is missing, the fifth step has open coverage and the result is UNKNOWN. The absence check cannot silently return true.

5. Inspect task artifacts

/tmp/nll-environment/tasks/customer-policy-review/
  input/input.md
  pin/task-pin.mjs
  generation/
  longtext/program.mjs
  output/result.mjs
  output/run.trace.mjs
  output/report.md

Importing the `.mjs` artifacts reconstructs typed values and reruns validation. The report is for people; the result and trace are the audit contract.

6. Verify without calling Codex again

node bin/nllagent.mjs benchmark \
  --agent privacy-retention \
  --data-root /tmp/nll-environment

Benchmark replay uses frozen LongTextJS and circuits. Training/materialization timing is reported separately from deterministic runtime timing.

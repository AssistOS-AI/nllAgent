Security for real JavaScript DSLs

Executable code is treated as executable code. The design separates module authority, document data, and semantic mutation instead of claiming that restricted syntax is a complete sandbox.

Document boundary

Markdown may contain instructions, code, prompts, or links; it remains source content. It cannot select imports, tools, models, circuits, skills, or policy. Exact anchors and typed translation outputs prevent source instructions from becoming project authority.

Module boundary

A selected agent root is trusted executable project code. Untrusted generated projects require a worker or process with a contained filesystem, import allowlist, injected tools/models, and resource budgets. The current CLI imports contained repository agents in-process and does not overclaim hardened hostile-code execution.

Semantic boundary

Even trusted stages do not receive mutable store internals. They query immutable terms and publish through an atomic transaction. External effects use named context methods and appear in trace. A failed stage publishes no partial facts.

Operational boundary

Agent names and paths are contained, process calls use argument arrays, secrets are excluded from artifacts, and stopped resources remain explicit. The remaining hardening work is listed in serious issues.

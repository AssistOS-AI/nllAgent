Production architecture

A production run, in the order it actually happens

Audit mode applies one immutable release to one immutable Markdown snapshot. It produces a canonical CNLAuditReport whose observations passed their declared verification path, or a stopped audit that names the missing contract, evidence, budget, or agreement.

flowchart TB
  SNAP[Input + active release snapshot] --> LTX[Compile + materialize LongTextJS]
  LTX --> GATE{Compatibility and coverage}
  GATE -->|ready| AUDIT[Execute + verify + CNL audit]
  GATE -->|stopped| AUDIT
  AUDIT --> RECORD[Persist canonical audit + Markdown view]

The production transaction. Judgment begins only after the document program satisfies the theory’s input contracts. Both success and refusal are persisted outcomes.

The two fixed inputs

A normal command names an agent and input file. The workspace’s active pointer selects a published release unless the command specifies an exact release. Before analysis, the runtime validates the Markdown file and named agent, reads the input, verifies the release, creates a run directory, copies input.md, and records the source and release digests in run.json.

nllagent run \
  --agent editorial-demo \
  --input manuscript.md \
  --output report.md

A release published while this command is running cannot change the run. A rerun with a different release or new model inference is a new transaction.

The execution path

  1. Create the structural document world. compileMarkdown() builds the source package, blocks, exact anchors, structural observations, view:whole, task, capabilities, closed-world structural coverage, gaps, and diagnostics. These deterministic objects exist before any model call.
  2. Load and compile the released theories. Each circuit listed by the release is loaded from JSON or restricted .circuit.mjs, normalized to plain data, linked to registered operators and verifiers, statically checked, and compiled. Its external input ports form the observation demand.
  3. Materialize only demanded semantic types. src/runtime/analyzer.mjs unions the circuit input types and selects matching released extraction profiles. The backend selector prefers configured AchillesAgentLib; otherwise auto uses the current Coding Agent reference adapter. Every returned candidate still passes the shared schema and exact-anchor materializer.
  4. Evaluate compatibility. The runtime compares the LongTextJS program with the release profile and each circuit contract. It checks concrete counts, types, accepted statuses, guarantees, producer capabilities, gaps, channels, structures, and coverage. Each circuit becomes ready or blocked; the aggregate becomes compatible, compatible with limits, or incompatible.
  5. Execute ready circuits. The scheduler supplies immutable typed observations to the graph, enforces node and wall-time budgets, invokes only registered capabilities, and preserves node outputs and trace. A circuit may emit a typed NeedObservation when it discovers a bounded missing premise.
  6. Perform bounded dynamic materialization. The analyzer collects those demands, invokes matching released profiles, and reruns the circuit. The default maximum is two dynamic rounds. A critical demand still unresolved at the limit makes the run incomplete; it does not become an absent fact.
  7. Verify and publish findings. Verifier nodes inspect candidate witnesses. Rejections remain in verifier-results.json and can create an issue, but do not become findings. Conflicting verified findings become review-required-conflict.
  8. Assemble the CNL audit. src/report/cnl-audit.mjs converts every published finding into a CNLAuditObservation and binds it to status, release, source digest, compatibility, coverage, conflicts, limitations, and any processing issue. The deterministic renderer derives report.md from this canonical object.
  9. Persist the transaction. The runtime writes the document program, compatibility decision, coverage, circuit plan, trace, findings, conflicts, verifier results, model captures, cnl-audit.json, its Markdown view, terminal status, and any issue.

Concrete path: the released weak-phrase rule

The input contains “In fact” in an ordinary paragraph. The published circuit needs document.paragraph@1 with extracted status and closed-world coverage. The deterministic Markdown compiler supplies both, so no semantic backend is needed for that port. Compatibility marks the circuit ready.

The lexical operator scans all supplied paragraph observations, applies the released term, locale, whole-word, case, scope, and dialogue-prefix policy, and constructs a candidate with its exact anchor. text.exact-match@1 rereads the source span. If it accepts, the finding includes ED-001, the source-rule reference, passage, verdict, severity, explanation, remediation, limitation, and verifier result. If the same phrase occurs in a dash-prefixed dialogue paragraph, the released scope convention excludes it before publication.

Concrete semantic variant: object continuity

The offline integration suite also exercises a long-range path in which a translation backend proposes anchored leave and use events for the same object. A state circuit replays the event policy and may request intervening retrieve, transfer, or replacement events. If the released producer materializes none with adequate scope, the witness records both source events, identity evidence, state history, search domain, and coverage. The verifier checks the replay. The result can be evidence-certified for that replay while still retaining the model-assisted status of the event semantics.

If the source cannot establish identity or intervening coverage, the circuit must not report a certified continuity violation. The run becomes limited, incomplete, or conflicted according to which contract failed.

Concrete normative audit: evidence is incomplete

A legal or policy release can audit an incident notice against precompiled definitions, authority, deadlines, exceptions, and evidence policy. Suppose the source proves the confirmation time but supplies only a partial email export rather than the complete official notification log. LongTextJS records the available evidence and open-world coverage. The circuit may calculate the possible deadline, but it cannot turn “not found in this export” into “notification did not occur.”

The resulting CNLAuditObservation can therefore say undetermined, cite the applicable article and supplied record, explain that the closed-world premise is missing, and request the official log. This is a useful legal audit result precisely because it refuses a stronger non-compliance claim than the evidence supports.

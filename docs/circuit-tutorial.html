From source text to verified output, one value at a time

How a CircuitJS program actually runs

First time here? Start with the five-minute Quick Tutorial. This page is the detailed follow-up with compilation, runtime values, semantic observations, and traces.

This tutorial starts with no assumed compiler or logic background. By the end, you should be able to look at a LongTextJS observation, a CircuitJS graph, and a runtime trace and explain what value moves at every step, who is allowed to transform it, and why a candidate cannot silently become a finding or plan.

The central intuition. LongTextJS is the addressable memory of one concrete source. CircuitJS is a frozen dataflow program of reusable judgment. A port connects the two. An operator proposes or transforms data. A verifier checks a bounded property. emit publishes only the accepted value.

1. Five objects to understand first

ObjectBeginner's questionExample
SourceWhat exact text or idea did the user supply?De fapt occurs at a Unicode range in one Markdown snapshot.
LongTextJS observationWhat typed thing did the compiler observe, and where?An extracted document.paragraph@1 linked to the range containing the paragraph.
CircuitJS portWhat kind of observation does this theory agree to consume?Many extracted paragraphs, under closed-world structural coverage.
Node outputWhat new immutable value did one declared operation produce?A candidate with an exact-text witness, or an empty collection.
Published outputWhich checked value is allowed to leave the graph?A verified finding for CNL/Audit-1, or a verified plan for CNL/Plan-1.

A circuit does not “read the document” in the vague sense. It receives only the records bound to its input ports. It does not “think inside the arrow.” Every computational arrow names a core primitive or a registered, versioned operator. Values are plain data and remain inspectable before and after each node.

3. Compilation time and execution time are different

This distinction prevents many misunderstandings. Compilation asks whether a theory is a valid, schedulable program. Execution asks what that already-qualified theory produces for one LongTextJS instance.

Compilation and qualificationProduction execution
Parse the restricted .circuit.mjs author expression into JSON-compatible data.Load the immutable compiled graph selected by the run's release.
Validate circuit identity, semantic version, purpose, ports, nodes, outputs, and finite budgets. Compile the current source into LongTextJS and evaluate compatibility.
Reject unknown operators, unknown verifiers, malformed references, hidden effects, and ordinary cycles. Bind observations that match the declared nominal type and accepted status.
Build the dependency graph and deterministic topological order.Resolve each node's $port and $node references to immutable values.
Reject dead nodes or unused ports that cannot affect a declared output.Execute ready nodes, enforce budgets, apply guarantee ceilings, cache deterministic outputs, and append trace records.
Prove verification dominance and derive the external observation contract by backward slicing. Return outputs, per-node values, trace, duration, and later the CNL artifact.
Link every critical demanded port to an approved producer and pass natural benchmark cases.Never modify the circuit, rulebook, benchmark, or active release.

4. How values move: port() and node()

The author helper port('paragraphs') becomes plain data { "$port": "paragraphs" }. The helper node('matches') becomes { "$node": "matches" }. They are references, not JavaScript function calls executed during production.

inputs: {
  observations: port('paragraphs'),    // external LongTextJS records
  rules: [{ id: 'ED-001', term: 'de fapt', /* released policy */ }]
}

inputs: {
  candidates: node('matches')          // immutable output of an earlier node
}

Before a node runs, the scheduler recursively resolves these reference objects. Constants remain constants, $port becomes a bound observation collection, and $node becomes the earlier node output. The result is hashed and passed to the registered implementation. This is ordinary explicit dataflow—not hidden state shared between nodes.

flowchart TB
  PORT[LongTextJS → bound paragraphs port] --> CALL[call operator]
  CALL --> CAND[FindingCandidate + witness]
  CAND --> VERIFY[verify witness]
  VERIFY --> EMIT[emit accepted findings]

Each box returns a value. Empty arrays move through the same path. An empty result is different from incompatibility, verifier rejection, or runtime failure.

5. The scheduler, line by line in plain language

  1. Fix budgets. The runtime selects the smaller applicable node and wall-time limits from the circuit and run configuration. Too many nodes stop before execution.
  2. Bind external ports. For each port, it filters program.observations by exact nominal type and accepted status, then enforces one, optional, many, or at-least-one cardinality.
  3. Follow compiled order. The current executor evaluates the compiler's deterministic topological order. Independent-node parallelism is a contract direction, not a behavior claimed by this local executor.
  4. Resolve node inputs. It replaces reference objects with the port or prior-node value and computes an input digest.
  5. Calculate a guarantee ceiling. If any material input is only proposed or model-judged, a later deterministic calculation cannot upgrade the final semantic guarantee beyond that premise.
  6. Choose the implementation. verify calls the verifier registry; emit calls the trusted publication routine; simple control nodes use core behavior; all other computational nodes require an exact registered operator.
  7. Use a safe cache when allowed. Deterministic node output may be reused only under a key that includes the circuit, implementation, inputs, complete LongTextJS program, and operational context.
  8. Record, do not narrate. The trace stores node identity, primitive, implementation, input and output digests, cache hit, and duration. Full node values are separate structured outputs.
  9. Resolve circuit outputs. Named output references are resolved after all nodes complete. Audit findings or the plan then feed their canonical CNL assembler.

6. No match, rejected witness, and stopped circuit are not the same

SituationWhere it happensMeaning
No matchThe operator legitimately returns [].The released rule found no candidate in the compatible, covered input. Other rules or global quality remain unclaimed.
Verifier rejectionA candidate exists, but replay returns status: reject. The operator proposed a witness that the trusted checker could not reproduce. emit filters it out, and diagnostics can become an issue.
IncompatibleBefore or during port materialization.The source cannot supply a critical type, status, coverage, schema, or resource demanded by the theory. The system must not interpret this as a clean document.
IncompleteCoverage evaluation.The system may have candidates, but cannot support a global or absence-based conclusion over the promised domain.
Budget exhaustedScheduler, node, search, dynamic demand, or model call.Computation did not complete under approved resources. A diagnostic candidate is not a publishable answer.

7. What changes for semantic observations

The lexical example is mechanical because Markdown structure and exact spans are deterministic. A continuity or focalization circuit often needs observations such as narrative.object-event@1 or narrative.mental-access@1. A model may propose them, but the same interface applies:

flowchart TB
  TEXT[Anchored source → schema-bound extractor] --> PROPOSED[Proposed observation → typed port]
  PROPOSED --> STATE[Circuit reasoning → witness]
  STATE --> VERIFY[State or structural verifier]
  VERIFY --> LIMITED[Bounded audit finding]

Deterministic replay does not erase interpretation. A state verifier can prove that the supplied event sequence has a gap. It cannot prove that a model classified every event or identity correctly unless those premises have their own stronger evidence.

For example, a model may propose “Mara left phone-1 in the car” and later “Mara used phone-1 in the hotel.” A continuity operator orders all materialized events and looks for retrieve, transfer, or replacement transitions. Its witness includes both events, the object identity, the intervening event domain, and coverage. The verifier replays the state transition. If extraction between the scenes is incomplete, the responsible result is incomplete or review-required, not a certified continuity error.

8. Why planning circuits reuse the machinery but not the validation graph

A validation graph asks, “Does this fixed document contain a witness for a rule outcome?” A planning graph asks, “What ordered, idea-specific document design follows from the released theory?” They share source grounding, types, authority, operators, budgets, provenance, verification dominance, and release identity, but their graph direction differs.

Validation pathPlanning path
document.paragraph@1, events, claims, or evidence enter ports. document.line@1 or domain idea observations enter ports.
Operators select, derive, compare, or maintain candidate violations and conclusions.Operators construct document design, ordered content, dependencies, required facts, and realization guidance.
A finding verifier checks its witness.The plan verifier checks source-idea binding, structure, authority, and rule-to-plan locations.
emit produces findings later assembled into CNL/Audit-1.emit produces one CNLGenerationPlan rendered as CNL/Plan-1.
The output says what was established about an existing source.The output says what a future source should contain for this idea. Optional realization must return to validation.

9. How to read a real trace without guessing

{
  "node": "verified",
  "primitive": "verify",
  "verifier": "text.exact-match@1",
  "inputDigest": "sha256:...",
  "outputDigest": "sha256:...",
  "cacheHit": false,
  "durationMs": 0.214
}
  1. Find the circuit identity and release in the run metadata. A node name alone is not globally meaningful.
  2. Use the compiled circuit to see which $port and $node values formed the input.
  3. Inspect the node output in nodeOutputs. For a verifier, read status, checked properties, diagnostics, certificate, and guarantee—not only the output digest.
  4. Follow witness observation identifiers to LongTextJS, then observation anchors to canonical source.
  5. Check coverage before accepting any statement based on “none found.”
  6. Check the next trace record is the expected emit path. The compiler already proves dominance, while the runtime still filters for accepted records.

10. Common wrong mental models

Wrong intuitionCorrect intuition
“LongTextJS is the formal truth of the document.”It is a versioned source model containing exact structure plus observations whose status and alternatives remain explicit.
“CircuitJS is JavaScript code generated by an agent.”It is a restricted plain-data graph. The MJS author form is stripped of JavaScript capabilities before compilation.
“Every node is an LLM prompt.”Most nodes are core dataflow or registered deterministic operators. A model-backed node must declare its role and effects.
“Verified means the entire interpretation is true.”Verified means one named checker accepted its declared property; the result retains the ceiling of uncertain premises.
“No finding means compliant.”It may mean no match under one rule, incomplete evidence, an inapplicable circuit, or an explicitly scoped clean audit. Read status and coverage.
“CNL contains the rules in friendlier words.”Rules stay in CircuitJS. CNL is the audit or idea-specific plan produced after the rules execute.
“The plan makes the generated text conformant.”The plan constrains and guides realization. Only the later audit can establish supported conformance.

11. Check your understanding

Why can an emit node not read directly from matches?

Because matches contains candidates. Static analysis requires the entire dependency path into emit to be dominated exclusively by verification. The runtime also filters records for an accepted verifier result.

Why does the paragraph port ask for closed-world coverage?

The rule promises to scan every qualifying Markdown paragraph, not only retrieved candidates. The structural compiler can certify that finite domain. Semantic absence claims require their own appropriate coverage.

If a model proposes an event and deterministic replay accepts the timeline, what is certified?

The state calculation is certified relative to the materialized event sequence. The event's semantic classification and identity remain at their original guarantee unless independently confirmed.

Why is the planning circuit separate from the validation circuit?

They solve inverse control-flow problems: detect outcomes in fixed text versus construct an ordered specification from an idea. They can share authority, rule identity, schemas, and operators without pretending the same graph computes both directions.

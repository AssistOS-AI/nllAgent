Models propose observations; the runtime owns the source world

From text passages to LongTextJS observations

Semantic translation is the narrow bridge between natural language and typed document observations. It exists because deterministic parsing can preserve paragraphs, lines, headings, and exact phrases, but cannot reliably identify every event, role, temporal relation, discourse mode, or domain concept required by a circuit.

Start with the LongTextJS document program if you need the surrounding source, anchor, status, coverage, and gap model. This page focuses only on the semantic materialization step.

What this layer does—and does not do

When a release circuit consumes narrative.object-event@1, the runtime needs observations such as “Alice left the phone in the car” and “Alice used the phone in the hotel,” including exact evidence, scope, negation, and modality. A translation backend receives a neutral demand and selected source fragments, then returns schema-bound candidate observations. The LongTextJS compiler validates and anchors those candidates before admitting them.

This path is not an always-on general ontology extractor. The release must list a versioned extraction profile, an output-reachable circuit port must demand that profile's exact outputType, and an approved backend must be available within budget. The current generic materializer adds schema-bound entries to observations; it does not automatically populate mentions, entities, or identityCandidates. Releases that need identity resolution must declare and test that additional producer contract.

The translator does not decide whether the two events form a continuity error. It does not see a hidden expected verdict, edit the active circuit, declare coverage by itself, or publish a finding. That separation keeps extraction errors distinguishable from rule errors and allows the same document world to be reused by several circuits.

flowchart LR
  NEED[Typed observation demand] --> CALL[Translation backend]
  CALL --> ANCHOR{Schema + exact anchor valid?}
  ANCHOR -->|yes| LTX[LongTextJS observation]
  ANCHOR -->|no| GAP[Explicit materialization gap]

Translation ends before judgment. The backend proposes structured candidates. The compiler checks their form and source grounding; only accepted observations enter LongTextJS, while failures become explicit gaps.

What remains deterministic

The runtime never pays a model to rediscover information it can compute exactly. Markdown ingestion, Unicode normalization policy, block identities, line and sentence observations, heading structure, source maps, occurrence counting, digests, exact-quote relocation, canonical serialization, cache keys, and the selected foundation's controlled-English scan are platform work. Models are reserved for richer semantic interpretations declared by extraction profiles.

Produced without a modelOften model-assisted

The foundation is deliberately narrow and open-world. A sentence outside its forms is not “missing data” and is not automatically sent to a model. Model-assisted materialization occurs only when an output-reachable release circuit demands a richer typed observation.

One backend-neutral request contract

src/model/translation-backends.mjs resolves a backend, but downstream compilation does not receive a vendor-specific response. All live and replay routes use the same canonical request digest, complete JSON Schema validation, observation normalization, exact anchoring, model-capture format, and guarantee propagation.

A translation request identifies the run, agent, release, extraction profile, observation schema and version, selected source blocks, accepted output fields, budget, and task role. The response contains candidates, quoted evidence, alternatives, and diagnostics in the requested schema. A backend capability says whether it supports translation or semantic benchmark evaluation; it does not grant filesystem or theory-authoring authority.

flowchart LR
  ROUTE{Backend selection} --> ACH[Achilles LLMAgent]
  ROUTE --> AGT[Coding Agent adapter]
  ACH --> CONTRACT[Canonical schema + capture]
  AGT --> CONTRACT
  CONTRACT --> COMP[LongTextJS compiler]

Replaceable inference, stable semantics. Achilles and the Coding Agent adapter may use different process protocols, but both must satisfy the same request, schema, capture, and source-grounding contract before the compiler sees their output.

Preferred backend: AchillesAgentLib

In auto mode, nllAgent first resolves AchillesAgentLib from an explicit override, environment configuration, a parent checkout, or local node_modules. Availability and provider configuration are separate. A library can be present while its selected provider still lacks a required credential; model inspect --json reports the module location, selected model, provider, missing environment input, and the backend that auto would choose.

When configured, nllAgent invokes its LLMAgent interface. Translation-class requests prefer a Spark model when the discovered configuration exposes one. The adapter supplies the complete schema and task tags, records the effective profile, and captures the result. Explicit --translator achilles fails if that path is not configured rather than silently selecting a different provider.

Fallback backend: a constrained Coding Agent

If Achilles is unavailable or unconfigured, auto selects the Coding Agent backend. This is not the learning workflow. For each semantic call, the adapter creates a small run-local folder, links only the nll-translate-longtext skill, writes the request and output schema, invokes the agent non-interactively, and reads one final JSON result. The agent receives no learning skills and no permission to edit release theory.

The current reference implementation is OpenAI Codex. That is why the public compatibility option is currently named --translator codex, the executable override is --codex-bin, and NLL_CODEX_BIN is recognized. Codex is an example of the broader Coding Agent role, not part of LongTextJS or CircuitJS semantics. Another adapter may use a different executable or protocol if it preserves workspace isolation, skill restriction, schema output, captures, timeouts, and capability boundaries.

Walk through one extraction call

Assume a continuity circuit demands narrative.object-event@1 and the source block reads: “Alice left her phone in the glove compartment.”

  1. Demand planning: the analyzer sees that no structural producer can create the required semantic type and selects the release’s extraction profile for that type.
  2. Neutral request: the profile supplies the observation schema, permitted event kinds, instructions to preserve negation and modality, source block identifiers, and the required exact quotation. It does not ask whether continuity is violated.
  3. Backend call: Achilles or the Coding Agent returns a candidate with kind leave, actor Alice, object phone, location glove compartment, and the quoted sentence.
  4. Compiler validation: the response must satisfy the complete nested schema. The quote is searched in the named block, an exact Unicode anchor is created, enums and fields are checked, and provenance records the profile and backend capture.
  5. Admission or gap: a valid candidate becomes a proposed LongTextJS observation. A missing quote, unknown field, wrong block, malformed response, or exhausted budget becomes a diagnostic and capability gap.
  6. Later judgment: CircuitJS can correlate this event with later events. The model response itself never becomes a finding.

Inspect and select the route

nllagent model inspect --json

# Normal selection: configured Achilles, otherwise Coding Agent fallback
nllagent run ... --translator auto

# Require one implementation
nllagent run ... --translator achilles
nllagent run ... --translator codex

# Deterministic-only execution
nllagent run ... --translator none

Use none when the release is deterministic or when policy forbids semantic inference. Circuits whose critical ports can be produced structurally may still run. Circuits requiring unavailable semantic types become incompatible; the report must not imply that they passed.

Captures, caching, and replay

Each semantic request has a canonical digest derived from meaning-bearing inputs rather than backend log details. Successful results are stored as model captures outside the source-truth layer. Replay can feed a prior validated response through the same schema and anchoring path, allowing tests and audits to reproduce circuit behavior without making a new inference.

Caching is safe only while the source block, schema, extraction profile, relevant context, task role, and backend contract remain identical. A cache hit reuses a captured proposal; it does not promote its epistemic status. Telemetry such as timing or retry count is retained for operations but excluded from the semantic digest.

Failure semantics and guarantee limits

ConditionRuntime behaviorWhat must not be inferred
Backend unavailable or explicitly disabledRecords missing translation capability; deterministic circuits may continue.That semantic observations are absent from the document.
Output violates schemaRejects the result, persists diagnostics, and may retry only under declared policy.That a partially parsed candidate is usable evidence.
Quotation cannot be located exactlyRejects or records a quality gap; no source anchor is invented.That a plausible paraphrase proves the observation.
Budget or dynamic-round limit reachedReturns incomplete or budget-exhausted for affected contracts.That the unobserved event did not occur.
Valid model-assisted observationAdmits it with proposed provenance and the release’s accepted status policy.That later deterministic processing turns it into a purely mechanical premise.

A deterministic verifier can certify that an exact passage, date calculation, or state replay follows from supplied premises. If a material premise was model-assisted, the final finding keeps the corresponding guarantee ceiling. Human confirmation is a separate status, not a cosmetic upgrade.

Implementation and tests

The backend resolver lives in src/model/translation-backends.mjs; Achilles integration and configuration inspection live in src/model/achilles-gateway.mjs; the shipped Coding Agent implementation lives in src/model/codex-translation-backend.mjs; materialization and anchoring are coordinated by src/longtext/compiler.mjs and src/runtime/analyzer.mjs. Tests use controlled LLMAgent.executePrompt() and process doubles so the default suite is deterministic and credential-independent. They cover route selection, Spark preference, complete schemas, Unicode and repeated anchors, request digests, captures, replay, Coding Agent workspace isolation, and an end-to-end semantic continuity circuit.

Those offline tests validate the integration contract, not a live provider’s quality. High-impact releases still need explicit live-profile evaluation against representative agent-owned cases, as recorded in serious issues.

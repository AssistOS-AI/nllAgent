Documentation / Why two DSLs

A document world and a reusable theory

Two DSLs, two CNL output profiles

LongTextJS and CircuitJS exist because the concrete source and the reusable method are different programs. They can be combined retrospectively to produce a CNL audit or prospectively to produce a CNL document specification.

The split in one example

A manuscript says that Alice left her phone in the car. Seven chapters later, it says that she used the phone in a hotel room. The manuscript supplies passages, events, identity candidates, order, and uncertainty. It does not itself define whether an omitted retrieval is a continuity error.

The editorial rulebook supplies the continuity policy: which actions change possession or location, how state persists, which narrative jumps count as explanations, what intervening events must be searched, and what evidence is required before publishing a finding. Changing that policy can change the verdict while the manuscript remains byte-for-byte identical.

flowchart LR
  TEXT[Manuscript passages] --> OBS[LongTextJS events + anchors]
  THEORY[Editorial rule → CircuitJS state policy] --> CONTRACT{Required observations available?}
  OBS --> CONTRACT{Required observations available?}
  CONTRACT --> FIND[Continuity finding or explicit unknown]

Observation is not judgment. The document program supplies addressable premises. The theory program supplies the reusable method. The contract decides whether the method has enough premises to run.

Created for one source revision and task. It preserves canonical text, structure, anchors, views, typed observations, identities, worlds, status, coverage, capabilities, gaps, and diagnostics. It is JSON-compatible data.

The JS suffix therefore does not authorize arbitrary JavaScript in either canonical language. It identifies a JavaScript-friendly ecosystem and, for circuit authors, a tightly restricted object-construction syntax. All published semantic artifacts are inspectable plain data before production execution. Making each LongTextJS document an executable module would let instance data acquire code authority, break canonical replay, and hide dependencies that the query and coverage analyzers must see.

This restriction applies to the two languages, not to platform implementation code. When a rule needs a real algorithm, a programmer writes it in a trusted runtime operator and keeps the circuit as explicit dataflow. See the runnable custom-operator example.

Why not use one universal representation?

A scene, a legal obligation, and a pressure measurement do not share the same truth conditions, scope, exceptions, or verifier. A giant ontology would move those differences into opaque payloads and operators. nllAgent standardizes a smaller common boundary—type, source, anchor, scope, status, coverage, binding, witness, and guarantee—while domain packages define the meanings they actually need.

The languages therefore do not need equal ontologies. LongTextJS may preserve observations unused by the current theory. CircuitJS may derive concepts, such as continuityViolation, that should never be extracted directly from source text. They need agreement only at output-reachable observation bindings.

LongTextJS nevertheless has a common upper ontology: mentions, scoped entity hypotheses, identity candidates, typed observations, scopes, worlds, time, status, provenance, alternatives, coverage, and gaps. What it does not have is an always-on domain ontology that declares every capitalized token an entity, every verb an actual event, or every discourse marker an emotion. Versioned domain packages add those schemas when a released circuit demands them, and uncertain interpretations retain proposed status.

The default foundation-core pack adds a smaller concrete baseline: documented controlled-English state assertions, explicit before relations, and bounded consistency circuits. This does not change the placement test. The source sentence remains a LongTextJS assertion; the incompatibility result remains CircuitJS judgment.

Where CNL fits without becoming a third competing world

CNL is an output family, not a third executable DSL. CNL/Audit-1 states what validation circuits established about one existing source. CNL/Plan-1 states what a future document should contain after planning circuits apply the same released knowledge to one idea. The plan records a rule-to-location witness, but it neither copies nor redefines the rules. LongTextJS remains the source world; CircuitJS remains executable judgment.

Query-first does not add a third authority

The experimental query-first profile makes the existing connection more explicit. It views one LongTextJS value as finite read-only relations and stores typed query and decision-table ASTs as plain data. Those values lower to the ordinary graph, registered operators, verifier, and emit path. They neither modify LongTextJS nor replace CircuitJS.

This is why the implementation does not use SQL or JavaScript callbacks. The useful abstraction is not “run arbitrary queries”; it is “state the selected domain, statuses, scope, coverage, dependencies, alternatives, witness, and verifier in one inspectable value.” The experimental subset implements exactly that bounded path and rejects unsupported forms.

Why the split remains executable

The CircuitJS compiler derives an observation contract from actual graph dependencies. Manual publication links every critical binding to a structural producer, extraction profile, or approved adapter. Production checks the concrete LongTextJS materialization and local matcher cardinality against that contract. This prevents two independently named vocabularies from merely looking compatible.

Benchmarks protect semantic behavior

A benchmark case is an executable module beside human-readable input and notes. It checks expected terms and statuses, not byte-for-byte report prose.

benchmarks/cases/unexplained-use/
  input.md
  case.mjs
  expected.mjs
  notes.md

export default benchmarkCase(
  'unexplained-use',
  './input.md',
  findingCount(1),
  containsFinding('continuity-gap')
);

Case families

Each material rule should have a positive, close negative, exception, incomplete evidence, open and closed absence, ambiguity, conflict, and incompatible-ontology case where meaningful. Long-range cases cross file or section boundaries.

Mutation

Semantic mutants invert comparisons, remove exceptions, forge coverage, promote proposed claims, merge identities, drop evidence, or bypass verification. Expected programs stay fixed. A surviving relevant mutant identifies an inadequate benchmark.

What the demo proves

The editorial benchmark proves ten deterministic cases for whole-phrase detection, dialogue/code exclusions, and paragraph-scoped frequency. It does not establish statistical prose quality.

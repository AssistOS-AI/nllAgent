Complete current command reference

nllagent manual page

This page documents every command and option accepted by the current parser, including defaults, conflicts, path rules, persistent effects, output forms, and exit codes. The short --help text is a synopsis; this page is the operational reference.

Invocation. Installed packages expose nllagent. From this checkout, use node bin/nllagent.mjs before the same arguments. All examples below omit that interchangeable prefix.

nllagent run --agent NAME --input FILE.md --output REPORT.md [OPTIONS]

Argument grammar and universal restrictions

RuleExact behavior
Command wordsrun, plan, benchmark, and learn use one word. The other commands use exactly two positional words. Surplus positional tokens are errors.
Option formUse --name value. Short options and --name=value are unsupported.
Boolean options--json, --no-llm, and --help consume no value.
Value optionsEvery other option consumes exactly the following token. A value beginning with -- is treated as another option and therefore cannot be used as a value.
DuplicatesEvery option may appear at most once. Duplicate boolean and value options are usage errors.
Unknown optionsEach command has an allowlist. An option valid on another command is still an error here.
Help--help, including with a command, prints the complete synopsis and exits 0 before command execution.
PathsRelative --input, --output, --rules, --realize-output, and --data-root resolve from the process working directory. Absolute paths remain absolute. --codex-bin is passed to the adapter unchanged; a bare command uses process PATH, while a relative path is interpreted from that adapter call's isolated working directory.
Markdown inputrun and plan require an existing regular .md file containing valid UTF-8.
Agent namesNames match ^[a-z][a-z0-9-]{0,62}$ and resolve below the selected data root. They are identifiers, not paths.
VersionsRelease and candidate versions use exact semantic-version-compatible values. There is no implicit latest.
StreamsNormal command results go to stdout. Errors go to stderr. Human mode prints a compact summary; JSON mode prints the structured result or error.
No runtime-code option. The CLI intentionally has no --runtime-extension. A trusted extension executes with host authority, so an embedding application must load and install it through the ESM library API before injecting registries into a programmatic run. Ordinary document commands never double as arbitrary code loaders. See the host integration example.

run — audit one Markdown document

nllagent run \
  --agent NAME \
  --input DOCUMENT.md \
  --output REPORT.md \
  [--release VERSION] \
  [--foundation core|off] \
  [--translator auto|achilles|codex|none] [--no-llm] \
  [--codex-bin PATH] [--data-root PATH] [--json]

The command fixes the agent, source bytes, selected immutable release, and foundation; creates runs/<run-id>/; compiles LongTextJS; materializes demanded observations; evaluates compatibility; executes foundation and release circuits; verifies candidates; assembles CNL/Audit-1; persists the run; and copies the rendered report to --output.

OutputMeaning
--outputHuman Markdown report for successful and controlled stopped states.
runs/<id>/run.jsonTransaction metadata, immutable release identity, runtime backend, terminal state, issue ids, and finding count.
source and LongText artifactsinput.md, source-package.json, longtext.json, coverage.json, and exact foundation.json selection.
decision artifactscompatibility.json, circuit-plan.json, semantic-trace.json, findings.json, verifier-results.json, conflicts.json.
product artifactsCanonical cnl-audit.json, internal report.md, model captures, and any runtime issue.

Exit 0 means reported, including explicitly limited reporting; exit 2 means a finding crossed the release’s blocking severity threshold; exits 3–6 are controlled stop/review states. “No findings” is never automatically a compliance certificate.

plan — compile an idea into CNL/Plan-1

nllagent plan \
  --agent NAME \
  --input IDEA.md \
  --output PLAN.cnl.md \
  [--release VERSION] \
  [--foundation core|off] \
  [--translator auto|achilles|codex|none] [--no-llm] \
  [--codex-bin PATH] [--data-root PATH] [--json]

Plan-only mode creates planning-runs/<id>/, compiles the idea into LongTextJS with the selected ontology metadata, executes the release’s primary planning circuit, verifies its rule-to-plan witness, persists canonical cnl-plan.json and rendered plan.cnl.md, and copies the rendering to --output. Foundation validation applies to each optional realized document. Deterministic planning works with --translator none; semantic idea observations may still require a backend according to the release.

Optional realization and revision

nllagent plan ... \
  --realize-output DRAFT.md \
  [--max-revisions 0..10] \
  [--translator auto|achilles|codex]

Realization is explicit. The backend receives the verified CNL plan, returns Markdown, and every candidate is audited by the unchanged validation circuits. With default --max-revisions 2, the runtime may perform one initial realization and up to two repairs. Zero permits only the initial attempt. The final candidate is copied to --realize-output; every attempt retains its candidate, full validation artifacts, CNL audit, and trace below the planning run.

--max-revisions without --realize-output, a value outside 0–10, or realization with --translator none/--no-llm is a usage error. Exhausting revisions with findings exits 2. Validation incompatibility, incomplete coverage, budget exhaustion, and conflict retain exits 3–6.

benchmark — execute natural cases

nllagent benchmark --agent NAME [--release VERSION]
  [--foundation core|off]
  [--translator auto|achilles|codex|none] [--no-llm]
  [--codex-bin PATH] [--data-root PATH] [--json]

The active or selected published release and chosen foundation run against the agent-owned benchmark suites. Translation selection matters when materialization or semantic report comparison is required. none is suitable only when every selected case can execute deterministically. The command does not mutate circuits, publish releases, or write a report path. Exit 0 means every executed case passed; exit 9 means benchmark mismatch.

learn — stage candidate authoring

nllagent learn --agent NAME --rules FOLDER
  [--codex-bin PATH] [--data-root PATH] [--json]

The command snapshots Markdown authority, creates a disposable learning workspace, links only the five learning skills, invokes the reference Coding Agent boundary, validates its schema-bound result and changed paths, and promotes only permitted agent authoring artifacts. It may create or repair candidates but cannot publish or modify the active pointer.

No translator switch. Learning is a Coding Agent authoring workflow, not production semantic translation. It accepts --codex-bin but deliberately rejects --translator and --no-llm; older parser behavior accepted and ignored those values.

Exit 0 means the learning runner reached its schema-valid terminal result. Learning or promotion policy failure exits 10. The terminal result itself may be completed, needs-review, or blocked; inspect JSON or the learning-run artifacts.

agent init — create one isolated workspace

nllagent agent init --agent NAME
  [--description TEXT] [--language TAG]
  [--data-root PATH] [--json]

Creates the full workspace tree, writes agent.json, and links the repository learning skills. It does not create a candidate, publish a release, or write an active pointer. The default intended use is Markdown review through explicitly published circuits.

agent list — enumerate valid workspaces

nllagent agent list [--data-root PATH] [--json]

Lists valid regular agent directories, descriptions, intended uses, and active versions when present. Invalid or unsafe entries are not presented as agents. This command does not require that the root already contain an agent.

agent inspect — inspect project and active release

nllagent agent inspect --agent NAME [--data-root PATH] [--json]

Returns the agent manifest, workspace root, and active release manifest or null. It verifies an active release when one exists; it does not execute circuits.

issue list — read runtime and publication issues

nllagent issue list --agent NAME [--status STATUS]
  [--data-root PATH] [--json]

Returns issue JSON records in deterministic file order. --status performs exact equality against the stored status; it is not a fuzzy search and currently has no parser-side enum. The command does not change issue lifecycle state.

feedback add — append scoped review evidence

nllagent feedback add \
  --agent NAME --run ID --type TYPE --message TEXT \
  [--finding ID] [--role ROLE]
  [--data-root PATH] [--json]

Creates one immutable ReviewFeedback record under feedback/. The default role is reviewer; the default finding target is null. This command does not edit the referenced run or finding, validate a policy change, alter expected benchmarks, or update a release. A later learning job may consume authorized feedback as evidence.

release publish — manually freeze and activate a candidate

nllagent release publish --agent NAME --candidate VERSION
  [--translator auto|achilles|codex|none] [--no-llm]
  [--codex-bin PATH] [--data-root PATH] [--json]

This is the only current publication action. It validates the candidate, restricted circuits, authority links, planning contracts, producer-consumer alignment, available benchmark suites, candidate and benchmark snapshot stability, copied release integrity, semantic diff, file digests, and release reload. On success it atomically creates releases/VERSION/ and replaces active-release.json.

Translation selection applies to model-assisted benchmark evaluation during publication. none succeeds only when the selected publication checks need no model capability. Learning never calls this command. Publication failure exits 10 and does not leave a partial release or move the active pointer.

model inspect — inspect Achilles configuration

nllagent model inspect [--json]

Reports whether AchillesAgentLib can be resolved, resolution strategy and entry, whether provider configuration is complete, preferred translation model, resolved model, provider, required environment, reason, and the backend auto would select. It does not inspect an agent, data root, or Codex installation and makes no live model call.

Translation selection and precedence

BackendSelection and failure behavior
autoTry configured Achilles first. If unavailable or unconfigured, construct the reference Coding Agent translation adapter. This is the default.
achillesRequire a resolvable and configured Achilles LLMAgent. Missing configuration is an error; no automatic Codex fallback occurs.
codexUse the current OpenAI Codex implementation of the generic Coding Agent runtime boundary.
noneRegister no model-backed runtime operators. Deterministic rules may execute; critical semantic demands become compatibility gaps.

CLI --codex-bin overrides NLL_CODEX_BIN, which overrides codex. Achilles module path comes from ACHILLES_AGENT_LIB_PATH or compatibility variable NLL_ACHILLES_MODULE; provider-specific required environment is reported by model inspect --json. Credentials are not copied into run artifacts.

Workspace effects by command

flowchart LR
  INIT[agent init] --> AUTHOR[Agent authoring tree]
  AUTHOR --> CAND[learn: candidates + learning runs]
  CAND --> REL[release publish: immutable release]
  REL --> EXEC[run or plan: persistent execution artifacts]
  REL --> PLAN

Authority follows the arrows. Production commands never write the theory. Learning writes only staged authoring and candidate surfaces. Only manual publication changes the active release.

Human and JSON output

Without --json, commands print a one-line summary or formatted object. With --json, stdout contains the command result produced by the corresponding library function. On error, stderr contains { "error": { "code", "message", "details" } }. JSON mode does not suppress persistent artifacts, change exit codes, or turn Markdown delivery files into JSON.

Recommended automation patterns

# Inspect before a model-assisted run.
nllagent model inspect --json

# Pin a release for reproducible CI and capture structured status.
nllagent run --agent editorial --release 0.1.0 \
  --input manuscript.md --output audit.md --foundation core --translator none --json

# Keep plan-only generation deterministic when the release permits it.
nllagent plan --agent editorial --release 0.1.0 \
  --input idea.md --output plan.cnl.md --translator none --json

# Separate candidate building from the explicit publication action.
nllagent learn --agent editorial --rules ./rulebook --json
nllagent benchmark --agent editorial --json
nllagent release publish --agent editorial --candidate 0.2.0 --json

Troubleshooting order

  1. Use agent inspect --json to confirm the workspace and active release.
  2. Use model inspect --json when semantic materialization or evaluation is expected.
  3. Read terminal status before counting findings.
  4. Inspect compatibility and coverage before circuit traces for stopped or empty results.
  5. Inspect verifier records before changing a circuit when candidates were rejected.
  6. Compare explicit release versions and semantic diffs after an upgrade.
  7. Record feedback for reviewer evidence; use learning for theory changes; publish only as a separate maintainer action.

The typed joint between document and theory

How LongTextJS and CircuitJS actually connect

They do not connect because two fields happen to share a name. A compiled CircuitJS graph publishes an observation contract. Manual publication checks that approved LongTextJS producers can satisfy it. A production run checks that this document satisfied it now.

flowchart TB
  THEORY[CircuitJS graph] --> CONTRACT[Derived observation contract]
  PRODUCERS[LongTextJS producers] --> GATE{Alignment + run compatibility}
  CONTRACT --> GATE
  GATE --> RESULT[Ready circuit or precise blocked gap]

One contract, two checks. Release alignment establishes a valid production path in general. Run compatibility establishes that the concrete source, observations, statuses, resources, and coverage satisfy that path.

What the contract contains

For each external input port that can affect an output, the contract records the nominal types, version, cardinality, accepted epistemic statuses, required coverage, criticality, scope relation, and guarantee requirements. The current weak-phrase circuit compiles to this contract:

{
  "kind": "ObservationContract",
  "schemaVersion": 1,
  "circuit": "editorial.weak-phrase@0.1.0",
  "ports": [{
    "name": "paragraphs",
    "types": ["document.paragraph@1"],
    "cardinality": "many",
    "statuses": ["extracted"],
    "coverage": "closed-world",
    "critical": true,
    "scopeRelation": null,
    "guarantee": null
  }]
}

This says more than “the circuit reads paragraphs.” It says that model-proposed paragraphs are not an acceptable substitute, that the full qualifying paragraph domain must be covered, and that failure to provide the port blocks this circuit.

The connection is checked at four moments

  1. Circuit compilation derives actual demand. src/circuit/compiler.mjs walks backward from declared outputs through emit, verify, calls, joins, and derivations. Only external ports that can influence the result enter the contract. A circuit cannot hide an undeclared premise on a dead side path.
  2. Manual publication links producers. src/release/manager.mjs builds a producer-consumer matrix. Built-in Markdown structure, published extraction profiles, and approved adapters are compared with each critical port’s type, statuses, coverage, and guarantee. A critical port without a compatible producer rejects the candidate.
  3. Production checks materialization. src/runtime/compatibility.mjs evaluates the actual LongTextJS program. It checks observations, cardinality, statuses, capabilities, gaps, channels, structures, coverage, operational resources, and profile limits. A declared producer cannot manufacture evidence that this document did not yield.
  4. Execution verifies a witness. A ready circuit may compute candidates, but its finding contract still controls publication. The registered verifier checks the precise witness against source and released policy. Compatibility answers “may this theory run?”; verification answers “does this candidate support this claim?”

Worked example: “in fact” in narration

The current editorial-demo makes the complete joint visible:

  1. The Markdown compiler produces every paragraph as document.paragraph@1 with extracted status, exact anchors, stable order, and verified closed-world structural coverage.
  2. The CircuitJS port asks for exactly that type, status, and coverage. Pre-publication checks link it to markdown-structural@1.
  3. During a run, compatibility confirms that the concrete view:whole has qualifying paragraph observations and no blocking structural gap.
  4. The lexical operator searches those observations using the published English phrase rule and dialogue-prefix exclusion. It returns candidates with anchors and rule provenance.
  5. The exact-match verifier reads the source range again. Only accepted candidates become findings. The report can therefore claim an exact occurrence in released scope, not a general aesthetic truth.

What changes for semantic observations

Suppose a continuity circuit consumes narrative.object-event@1. Its published extraction profile may produce proposed leave, retrieve, transfer, and use events. Pre-publication checks can prove that a producer exists and that natural benchmark cases give the type operational meaning. Production can prove that candidate events were anchored and that the required scope was processed. A state verifier can replay the published transition policy.

None of those steps turns model interpretation into mechanical fact. The final guarantee is bounded by the event status, identity evidence, and coverage. If the phone identity is ambiguous or the intervening chapters were not materially covered, the correct result is ambiguous or incomplete. This is why the connector includes status and coverage rather than just a JSON schema.

No producerA circuit consumes normative.notification@2, but the release ships neither a structural producer nor an extraction profile.Manual publication rejects the candidate.

Why this architecture works

The document compiler is guided without being told which verdict to produce. The theory is reusable without pretending to understand every source. Static linking catches impossible packages before release. Runtime compatibility catches concrete documents outside the calibrated domain. Witness verification catches bad candidates after execution. Each failure lands at a named boundary that can later become a targeted learning task.

The same joint supports both CNL profiles. Planning circuits demand structural or semantic observations from the idea and emit an idea-specific CNL specification with verified rule-to-plan coverage. Validation circuits demand observations from an existing or realized document and emit findings assembled into a CNL audit. Neither output copies the rulebook or bypasses its observation contract.

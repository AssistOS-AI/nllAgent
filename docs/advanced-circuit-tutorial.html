One executable scenario · four rule outcomes · final CNL

Combine observation matching, custom code, foundation circuits, and CNL

This tutorial runs a real repository example that combines three mechanisms without hiding their boundaries. A direct observation binding selects ordinary paragraphs. A trusted JavaScript extension computes a word-count rule. The default foundation independently checks explicit logic and arithmetic. The analyzer merges accepted findings into the actual CNL/Audit-1 report.

Scope. This is an integration tutorial for programmers. It does not teach how to publish arbitrary host extensions from the CLI; host code remains explicitly installed through the ESM API. Query-First joins and absence semantics are shown by contrast and linked to their executable tutorial.

1. Run the complete scenario

node examples/advanced-circuit/run.mjs

The command exits successfully and writes a CNL audit to standard output. The integration test runs the same function and asserts the terminal status, exact rule set, dialogue exclusion, support anchors, rule basis, and rendered explanation:

node --test tests/integration/advanced-circuit-example.test.mjs
flowchart LR
  M[Markdown] --> L[LongTextJS + foundation observations] --> B[observation binding]

Two theories share one source world. The agent circuit and foundation circuits do not call one another. They consume different typed observations, verify their own witnesses, and meet only when accepted findings are assembled into CNL.

3. The selector is not the graph reference

inputs: {
  narrativeParagraphs: observationBinding({
    type: 'document.paragraph@1',
    statuses: ['extracted'],
    cardinality: 'many',
    coverage: 'closed-world',
    critical: true,
    where: [{
      path: 'payload.structuralRole',
      operator: 'eq',
      value: 'paragraph'
    }]
  })
}

This declaration performs selection. It filters type, status, and the local field, then checks cardinality. The node reference below performs no matching:

inputs: {
  paragraphs: binding('narrativeParagraphs'),
  maximumWords: 12
}

binding() produces the canonical $port graph reference. The older port() helper is an exact compatibility alias. The distinction matters: changing a matcher changes which LongTextJS rows enter the graph; changing a node reference changes dataflow among already constructed values.

4. Choose the smallest mechanism that preserves meaning

QuestionUseWhy
Does this one observation have a known local field value?observationBinding.whereOne scan, AND-only comparisons, no hidden epistemics.
Which rows match another relation, decision row, or covered absence?Query-FirstJoins, dependencies, unknown, and coverage remain explicit.
Does the rule need parsing, dynamic programming, state, a solver, or numerical work?Registered operator or runtime extensionReal code has schemas, limits, tests, and a verifier.
Does the algorithm iterate?fixpoint, maintain, or search operatorThe graph stays acyclic while termination lives in one budgeted contract.

For example, “ordinary paragraphs” is a local matcher. “Obligations without a qualifying notice” is not: it needs a join and exact closed-world coverage, so it belongs in the Query-First tutorial. “Count words using a published tokenization policy” is executable work and belongs behind an operator.

5. The JavaScript node has executable contracts

The extension declares structured schemas. This shortened fragment is still real syntax:

inputSchema: {
  type: 'object',
  required: ['paragraphs', 'maximumWords'],
  additionalProperties: false,
  properties: {
    paragraphs: { type: 'array', items: OBSERVATION },
    maximumWords: { type: 'integer', minimum: 0 }
  }
},
outputSchema: {
  type: 'array',
  items: CANDIDATE
}

Compilation rejects a missing maximumWords, an unknown input, or a string threshold. Runtime then validates the resolved observations and every returned candidate. The verifier has separate input/output schemas and independently reconstructs the count and source anchor. The release locks the extension source digest, so changing function bytes without changing the graph cannot reuse publication or cache identity.

The paragraph contains 19 words; the configured maximum is 12.

The support-anchor id is shortened here and explicitly marked with an ellipsis because it is content-derived; run the example for the exact id and source digest. The test does not compare that abbreviation. It asserts that the real report contains a paragraph anchor and authority reference. This end-to-end check caught and fixed an earlier custom candidate that had a main anchor but omitted support anchors and rule basis.

7. Useful experiments

  1. Change maximumWords to 20. The custom finding disappears; the two foundation findings remain.
  2. Change the matcher value to dialogue-line-candidate. The dialogue paragraph becomes the selected custom subject.
  3. Remove one door assertion. The logic finding disappears without changing the custom circuit.
  4. Replace the arithmetic sentence with 2 times 3 equals 6.. Exact replay produces no math finding.
  5. Replace maximumWords: 12 with a string. Compilation fails with circuit-schema-mismatch before JavaScript executes.

These are changes to source or candidate authoring files. Do not edit a published release in place. The test suite uses fresh data and immutable compilation to preserve that boundary.

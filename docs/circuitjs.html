CircuitJS: executable business judgment

A circuit has one semantic responsibility and may compose several methods. It can expose declarative structure where useful and keep an irregular algorithm as ordinary instrumented JavaScript.

A real four-valued retention decision

const STATUS_TABLE = decisionTable(
  'privacy-retention-status',
  columns('duration-comparison', 'documented-exception'),
  row(values(CONFLICT, anyValue()), result('CONFLICT'), 100),
  row(values(anyValue(), CONFLICT), result('CONFLICT'), 100),
  row(values(FALSE, anyValue()), result('SATISFIED'), 80),
  row(values(TRUE, TRUE), result('ACCEPTED_EXCEPTION'), 80),
  row(values(TRUE, FALSE), result('VIOLATED'), 80),
  row(values(TRUE, UNKNOWN), result('UNKNOWN'), 80),
  row(values(UNKNOWN, anyValue()), result('UNKNOWN'), 70),
  'priority'
);

The table cannot coerce unknown exception coverage into “no exception.” Equal-priority incompatible rows produce conflict instead of first-row-wins behavior. Decision-table identity and selected rows appear in the circuit model and trace.

Normal JavaScript remains normal

const assessRetention = stage(
  'privacy-retention.assess-records',
  async (ctx) => {
    const groups = new Map();
    for (const declaration of ctx.store.instancesOf(RetentionDeclaration)) {
      const id = declaration.value(recordId);
      groups.set(id, [...(groups.get(id) || []), declaration]);
    }
    for (const [id, declarations] of groups) {
      // typed comparison, exception resolution, decision and verification
      const verified = await ctx.verify(`retention-evidence-${id}`, verifier);
      if (verified) ctx.emit(buildAssessment(id, declarations));
    }
  },
  reads(RetentionDeclaration, ExceptionEvidence, ExceptionCoverageEvidence),
  writes(Finding)
);

The runtime does not transform the loop and map into decorative graph nodes. The stage is a macro-node with declared inputs/effects, a transaction, and trace. Local objects never enter SemanticStore.

Typed rules and absence

For naturally relational rules, constructors also build Patterns:

rule('notice-missing',
  when(
    match(Incident(actor(supplier), within(serviceScope))),
    notExists(
      match(Notice(actor(supplier), about(ref('incident')))),
      serviceScope,
      requireCoverage(Notice)
    )
  ),
  then(emit(({ incident }) => MissingNotice(evidenceOf(incident))))
);

An open scope leaves the rule condition unknown and does not run then. Each binding, absence result, and action is traced.

Dynamic and hierarchical composition

instantiateEach creates one canonical subcircuit instance per semantic binding. Subcircuits and scheduled stages preserve typed ports. Positive recursive cycles are explicit fixed-point groups; accidental capability cycles fail planning.

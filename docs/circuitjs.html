The theory side

CircuitJS is a program of the rulebook

CircuitJS turns reusable rule knowledge into a typed declarative graph. Validation graphs publish verified findings that become a CNL audit; planning graphs publish a verified CNL document specification. Both state what observations are required, how rules apply, and what must be checked before publication.

New to graph execution? Use the interactive circuit execution tutorial first. It lets you move from a source through LongTextJS, port binding, operator output, witness replay, emit, and both CNL profiles one stage at a time.

A theory has a different lifecycle

A production document may change daily. A published rule theory should remain stable across many documents until authority, evidence, or feedback justifies a new release. CircuitJS is therefore authored and tested in learning, locked into an immutable release by a manual publication command, and only read during production.

flowchart TB
  AUTHOR[Rulebook → restricted author form] --> GRAPH[Canonical plain-data graph]
  GRAPH --> STATIC[Static compilation + linking]
  STATIC --> CHECKS[Natural benchmark checks]
  CHECKS --> REL[Manual immutable publication]

The theory becomes production code only through an explicit manual publication command. The author notation cannot add executable capabilities. Static analysis and natural cases must agree before the graph is frozen into a release.

A circuit that exists in the repository

The editorial-demo candidate contains this restricted author module. It finds the exact English phrase “in fact” only in published narrative paragraph scope and publishes a finding only after replay verification:

export default circuit({
  kind: 'CircuitJS',
  id: 'editorial.weak-phrase',
  version: '0.1.0',
  description: 'Find “in fact” in narrative Markdown paragraphs.',
  sourceRuleReferences: [
    'authority/style-guide.md#rule-ed-001-weak-phrase-in-narration'
  ],
  inputs: {
    paragraphs: {
      type: 'document.paragraph@1',
      cardinality: 'many',
      statuses: ['extracted'],
      coverage: 'closed-world',
      critical: true
    }
  },
  nodes: [
    {
      id: 'matches',
      primitive: 'call',
      operator: 'text.lexical-occurrences@1',
      inputs: { observations: port('paragraphs'), rules: [/* ED-001 */] }
    },
    {
      id: 'verified',
      primitive: 'verify',
      verifier: 'text.exact-match@1',
      inputs: { candidates: node('matches') }
    },
    {
      id: 'findings',
      primitive: 'emit',
      inputs: { verified: node('verified') }
    }
  ],
  outputs: { findings: node('findings') },
  budgets: { nodes: 12, wallTimeMs: 5000 }
});

How to read the graph

  1. Identity and authority. The circuit has a semantic version and a source-rule reference. A finding can therefore return to the rulebook passage that authorized it.
  2. Typed port. paragraphs accepts many document.paragraph@1 observations, but only with extracted status and closed-world coverage. It is critical, so a missing producer blocks the circuit.
  3. Registered computation. call invokes text.lexical-occurrences@1. The circuit supplies policy data; the operator supplies reviewed executable behavior.
  4. Independent check. verify gives the candidate and source evidence to text.exact-match@1. A rejected candidate never reaches the output.
  5. Controlled publication. emit consumes only the verified result. Static analysis proves that every path to this output is verification-dominated.

Why the file looks like JavaScript but is not general JavaScript

The loader accepts exactly one direct export default circuit({...}) expression and injects the data constructors circuit, port, and node. It rejects imports, wrappers, functions, classes, control flow, asynchronous work, templates, dynamic code generation, process, filesystem, network, prototype mechanisms, accessors, cycles, non-finite numbers, and values that cannot be converted losslessly to plain data.

The expression is evaluated briefly in a restricted node:vm context and normalized. The CircuitJS compiler then treats the result exactly like JSON. Domain logic must live in a registered operator with a declared signature, effect set, budget, and verifier—not inside an author-supplied callback.

Ports are the public interface of a theory

Inputs declare nominal type and version, cardinality, accepted statuses, coverage, criticality, scope relation, ordering, deduplication, and guarantee requirements. The compiler traces which inputs can actually affect an output and persists an ObservationContract. Dead declarations and hidden side paths are rejected.

This is how CircuitJS asks the document side for neutral premises without sending the desired verdict. The weak-phrase circuit asks for all qualifying paragraphs. A continuity circuit asks for leave, retrieve, transfer, and use events—including negated or hypothetical candidates—not for “evidence that continuity is broken.”

The runtime currently implements the static core and a set of deterministic relational, temporal, state, unit, interval, fixpoint, argumentation, lexical, semantic, and replay operators used by tests and example packages. The broader primitive catalog is an extension contract; unsupported semantics must block rather than appear to work.

Validation circuits and planning circuits

A normal circuit has validation purpose and publishes findings. The runtime collects those findings into CNLAuditReport, the CNL/Audit-1 profile. A purpose: planning circuit consumes LongTextJS observations of one high-level idea and publishes a verification-dominated CNLGenerationPlan, the CNL/Plan-1 profile. Its construction node must map every applied rule to concrete locations in the plan. Validation circuits cannot embed CNL constraint projections: rules remain executable theory. Releases list the two graph families as circuits and planningCircuits.

One rule technology, two verified CNL products

NaturalLanguageLinterAgent

nllAgent turns rules written for people into versioned, specialized document agents. The same LongTextJS–CircuitJS architecture has two explicit modes: audit an existing document into a CNLAuditReport, or compile an idea into a verified CNLGenerationPlan specification. Final prose may be realized later by an LLM, but the specification exists and is checked first.

Two modes, not two unrelated products. In audit mode, circuits publish verified observations about correctness, compliance, or quality as CNL/Audit-1. In specification mode, planning circuits publish CNL/Plan-1, an idea-specific plan for a document. Rules remain in CircuitJS in both modes; CNL is the controlled output.

New readers should begin with the Quick Tutorial: one source contradiction, one default rule, and one three-node circuit shown in author DSL. Then read Circuits, without the mystery for a practical account of port binding, filtering, multiple records, cycles, and custom JavaScript operators. Continue with Concepts and foundations for vocabulary, scientific lineage, guarantee levels, and ethical commitments.

The problem it solves

Organizations already have the knowledge needed to review or create documents, but it is scattered across style guides, laws, regulations, procedures, technical standards, examples, and reviewer decisions. A generic LLM prompt can read some of that material and produce a plausible answer, but it does not create a stable specialized agent: the applicable rule can drift between calls, a distant exception can be missed, an absent fact can be invented, and the model can write a convincing explanation for its own mistake.

Long documents make this worse. Placing a manuscript and an entire rulebook in one large context does not create persistent character identity, a timeline, rule priority, evidence coverage, or a replayable method. Information in the middle can be overlooked, and a larger context window still does not provide an independent verifier. nllAgent instead compiles each domain into a versioned agent whose observations, rules, exceptions, algorithms, benchmarks, and limits can be inspected and reused.

The approach is neuro-symbolic in a practical sense. Neural models interpret ambiguous language, propose typed observations, and realize CNL plans as fluent text. Persistent symbolic artifacts preserve source anchors, identity, time, state, rule priority, coverage, and executable control. Deterministic operators and trusted verifiers check the properties they can actually prove; model-assisted premises retain a lower guarantee ceiling and can require human review.

A useful result must therefore survive concrete questions: Which passage established the premise? Which release and rule were applied? Was the evidence complete enough to conclude that something was absent? Did a model merely propose an event, or did a checker verify the final property? nllAgent publishes through the declared verification path and stops with a precise gap when the specialized agent lacks the required language, evidence, or capability.

The complete mental model. Both branches produce a typed CNL artifact. Audit describes an existing source; specification describes what a future source should become. The dotted realization branch is optional and returns through audit.

LongTextJS: the document side

One production document becomes source blocks, exact anchors, structural and semantic observations, scopes, alternatives, coverage, capabilities, gaps, and a task. It says what this run knows about this source—not whether the source complies.

CircuitJS: the theory side

One rulebook lineage becomes typed ports, declarative nodes, registered operators, exceptions, budgets, verifiers, finding contracts, and links to authority. It is reused across documents and changes only through a new published release.

What happens during one verification

  1. The CLI fixes a named agent, an immutable release, and an exact Markdown input snapshot.
  2. The deterministic compiler creates LongTextJS structure and anchors, applies the small selected foundation, and materializes only the extra domain types demanded by the release’s circuits.
  3. The compatibility gate checks the concrete observations, statuses, cardinalities, resources, and coverage against the circuits’ observation contracts.
  4. Ready circuits execute. Registered verifiers inspect their witnesses before findings can be emitted.
  5. The run assembles verified findings into canonical CNLAuditReport, renders report.md, and persists both with the trace and any reusable issue.

This sequence is implemented in src/runtime/production-run.mjs and src/runtime/analyzer.mjs. The page Architecture of one verification follows the code path and files in order.

What happens during CNL generation planning

A high-level idea becomes a LongTextJS source. A published purpose: planning circuit applies the domain theory and emits an idea-specific CNL plan with document design, ordered content, dependencies, guidance, and provenance. Its verifier also requires a rule-to-plan witness, so every applied rule names the concrete plan locations it shaped. This plan is the primary result and can be produced without an LLM. If requested, a model realizes it and the draft returns to audit mode. CNL generation planning follows both paths.

What happens during learning

Learning is a separate candidate-build system. Rules, calibration documents, reviewer feedback, and production issues are copied into a disposable staging workspace. A Coding Agent may propose schemas, extraction profiles, circuits, natural benchmark cases, and candidates. The host audits the resulting filesystem changes, but learning cannot publish. A maintainer later runs release publish explicitly; that command checks the chosen candidate, snapshots immutable bytes, creates the release, and selects it for future runs.

Production therefore never edits the theory that is judging its current input. Read Architecture of learning for the lifecycle and Learning workflow for the operational commands.

Run the included agent

The repository includes editorial-demo, with authority material, circuits, natural benchmark cases, one published MVP baseline, and an active release pointer:

node bin/nllagent.mjs benchmark --agent editorial-demo

node bin/nllagent.mjs run \
  --agent editorial-demo \
  --input data/editorial-demo/benchmark/public/weak-phrase/input.md \
  --output /tmp/editorial-report.md

node bin/nllagent.mjs plan \
  --agent editorial-demo --release 0.1.0 \
  --input data/editorial-demo/examples/planning/idea.md \
  --output /tmp/editorial-plan.cnl.md \
  --translator none

report.md is the human view of cnl-audit.json; plan.cnl.md is the human view of cnl-plan.json. Their owning directories under runs/ and planning-runs/ contain the machine-readable evidence.

What exists today

The current implementation provides the Node.js 22+ ESM library and CLI, Markdown ingestion with source maps and Unicode-aware anchors, canonical LongTextJS data, a default versioned foundation for bounded logical, temporal, exact-arithmetic, elementary physical, and literal emotion/type consistency, restricted validation and planning CircuitJS modules, canonical CNL products, registered operators and verifiers, compatibility and coverage checks, persistent runs, isolated learning, natural benchmarks, and immutable published releases.

Host applications can also install a content-addressed NllRuntimeExtension containing real JavaScript operators and verifiers. The graph remains declarative, extension inputs and outputs remain plain data, and published uses lock the implementation digest. The standard CLI does not load extension paths.

Query-first CircuitJS is now an experimental part of that implementation. The restricted loader accepts its bounded plain-data query/table subset, compilation lowers it to ordinary CircuitJS, release artifacts retain its QueryContract and source map, and benchmarks compare reference with lowered execution. Current editorial examples remain direct because their three-node operator wrappers are already simpler. DS020 distinguishes this implemented subset from aggregates, patterns, native indexes, and stronger analysis that still remain future work.

It does not claim universal document understanding. Live model profiles are not exercised by the default offline checks; pre-publication checks do not yet execute generated semantic mutations, an independently implemented native query engine, shadow/canary traffic, or an agent-owned idea-to-plan and plan-to-document quality benchmark. Planning is structurally checked and covered by controlled integration tests, not by a statistical claim about prose quality. The registry also lacks complete machine-typed contracts for arbitrary semantic query schemas and advanced operators. These concrete limits remain in serious_issues.md.

The tutorial pages explain the implementation. The contiguous DS specification set defines the contracts.

Learning-plane architecture

Learning builds a new theory; it never edits a live one

A learning job compiles rulebooks, calibration documents, review evidence, and production gaps into candidate LongTextJS producers, CircuitJS theories, and natural benchmark cases. It stops at a candidate. A maintainer decides when to run the separate manual publication command.

flowchart LR
  INPUT[Rules + calibration + feedback] --> STAGE[Coding Agent builds candidate in staging]
  STAGE --> CAND[Audited candidate]
  CAND -. explicit maintainer command .-> PUB[Pre-publication checks]
  PUB --> REL[Immutable published + active release]

Learning is a candidate build pipeline. Open-ended authoring happens only in staging. Publication is a later, explicit development action that reruns trusted checks and updates the active pointer atomically.

The learning path

  1. Lock and snapshot the project. src/learning/runner.mjs acquires the named agent’s learning lock, copies the requested Markdown rules, selects open issues, records the active release, and creates learning-runs/<id>/. Each named agent therefore learns against its own authority, benchmark, and release lineage.
  2. Build a disposable workspace. The runner copies authoring roots—circuits, schemas, extraction, candidates, benchmark, and proposals—plus read-only context such as authority, feedback, issues, DS contracts, serious issues, the active release, and trusted registry descriptions.
  3. Expose only learning skills. src/learning/workspace.mjs links exactly five agent-local skills: scope the project, compile the theory, build the benchmark, learn from issues, and prepare a candidate for release. Production translation and unrelated repository-maintenance skills are absent.
  4. Let the Coding Agent author a coherent candidate. The agent may add or change observation schemas, extraction profiles, restricted CircuitJS modules, natural microcases, proposals, and candidate packages. For each relevant platform limitation it also records a capability gap as resolved, mitigated, or blocked. It returns a schema-valid terminal result. OpenAI Codex is the current reference adapter; the architecture depends on the generic staged-workspace and result contract.
  5. Audit every changed path. After the process exits, the host compares before and after snapshots. Deletions, symlinks, forbidden paths, non-regular files, absent output, and schema-invalid output reject promotion. Only whitelisted authoring files and current learning-run outputs are copied back to the real agent workspace.
  6. Stop at the candidate boundary. Learning records candidate versions and limitations but cannot call the release manager, write releases/, or change active-release.json.
  7. Publish only on explicit maintainer request. nllagent release publish validates the selected candidate, derives contracts, checks producer alignment, snapshots candidate and benchmark bytes, runs the available suites, and confirms neither snapshot changed.
  8. Publish and select atomically. A passing manual command copies the tested snapshots, writes benchmark results, semantic diff, impact map, observation contracts, alignment report, file digests, and publication.json, then publishes the immutable version and updates active-release.json. A failure leaves production unchanged.

What the Coding Agent is expected to build

The open-ended work is not “write a better prompt.” A useful candidate contains coordinated artifacts on both sides of the contract:

The shared foundation is not agent-owned. A learning job may query its observations and propose a platform extension, but it cannot edit foundation-core, its circuits, or its verifiers through an agent candidate. A changing world fact belongs in a separately sourced knowledge pack, not in an agent's claim of universal common sense.
ArtifactQuestion it answers

A blocked capability is still useful work when the missing layer is protected. The proposal must state the required observation or operator contract, structured value schemas, verifier boundary, budgets, and benchmark family. It must not manufacture identity from a matching name, infer absence from an empty open-world collection, invent unsourced world facts, or embed a JavaScript callback in a learned circuit. Those shortcuts make one case look solved while weakening the architecture.

Worked repair: dialogue is not narration

Assume a run reports the phrase “in fact” inside a line of dialogue, but the style rule applies only to narration. A reviewer rejects the finding and marks the disputed scope. The learning system should not add a document-specific exception.

  1. The issue is classified as a scope or observation-boundary failure, not a new normative rule.
  2. The smallest reproducer becomes a natural regression family: one narrative positive, one dash-prefixed dialogue negative, and one nearby boundary case.
  3. The candidate may change the structural producer, extraction profile, circuit scope policy, or their contract depending on where the trace shows the error. It states a falsifiable repair hypothesis.
  4. Existing cases must still pass. The new dialogue case must stop producing the finding. Manual publication verifies that the contract still has a producer and that the candidate and benchmark stayed unchanged during the checks.
  5. After manual publication, the original document may be rerun under the new active release. The old incorrect run remains auditable rather than being rewritten.

The current editorial-demo release embodies this distinction through its paragraph scope and released dash-prefix convention. Its benchmark contains positive, negative, exception, boundary, scope, and adversarial families rather than only the successful phrase match.

What the gate proves today

The implemented gate validates manifests, circuits, operator and verifier links, verification dominance, compatibility profiles, observation-contract alignment, available agent benchmarks, byte stability, copied snapshot integrity, semantic diff, impact map, and release digests. The learning skills also require a capability-gap report when a scoped serious issue applies; this report is review evidence, not proof that the missing platform feature exists.

Current publication-check limit. The command does not yet generate mutated CircuitJS or LongTextJS programs and calculate a mutation score. It also does not execute differential implementations, shadow/canary traffic, or a complete metric program. Natural cases stored in a mutations suite are valuable cases, but are not executed program mutation. The publication record reports only checks that actually ran.

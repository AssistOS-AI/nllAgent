Learning-plane architecture

Learning builds a new theory; it never edits a live one

A learning job compiles rulebooks, calibration documents, review evidence, and production gaps into candidate LongTextJS producers, CircuitJS theories, and natural benchmark cases. Host-side audit and qualification decide what may become a release. Activation remains separate.

flowchart TB
  INPUT[Rules + calibration + feedback] --> STAGE[Coding Agent builds candidate in staging]
  STAGE --> GATE[Host audit + trusted qualification]
  GATE --> REL[Immutable qualified release]
  REL --> ACT[Explicit activation for future runs]

Learning is a build pipeline. Open-ended authoring happens only in staging. The promotion audit controls files, the release gate controls semantics, and activation controls production policy.

The learning path

  1. Lock and snapshot the project. src/learning/runner.mjs acquires the named agent’s learning lock, copies the requested Markdown rules, selects open issues, records the active release, and creates learning-runs/<id>/. Each named agent therefore learns against its own authority, benchmark, and release lineage.
  2. Build a disposable workspace. The runner copies authoring roots—circuits, schemas, extraction, candidates, benchmark, and proposals—plus read-only context such as authority, feedback, issues, DS contracts, serious issues, the active release, and trusted registry descriptions.
  3. Expose only learning skills. src/learning/workspace.mjs links exactly five agent-local skills: scope the project, compile the theory, build the benchmark, learn from issues, and prepare qualification. Production translation and unrelated repository-maintenance skills are absent.
  4. Let the Coding Agent author a coherent candidate. The agent may add or change observation schemas, extraction profiles, restricted CircuitJS modules, natural microcases, proposals, and candidate packages. It returns a schema-valid terminal result and may write a qualification request. OpenAI Codex is the current reference adapter; the architecture depends on the generic staged-workspace and result contract.
  5. Audit every changed path. After the process exits, the host compares before and after snapshots. Deletions, symlinks, forbidden paths, non-regular files, absent output, and schema-invalid output reject promotion. Only whitelisted authoring files and current learning-run outputs are copied back to the real agent workspace.
  6. Validate the candidate structurally. Qualification reads the candidate manifest, compiles every circuit, links operators and verifiers, validates authority references and compatibility profiles, derives observation contracts, and builds the producer-consumer alignment report. A critical port without an approved producer fails here.
  7. Run natural benchmarks without mutable inputs. The gate snapshots candidate and agent benchmark bytes, runs all discovered suites and declared family requirements, then confirms neither snapshot changed. A failing benchmark or changed byte aborts qualification.
  8. Create an immutable release. A passing gate copies candidate and benchmark snapshots, writes benchmark results, semantic diff, impact map, observation contracts, alignment report, file digests, and qualification result, then atomically publishes releases/<version>/.
  9. Activate separately. Qualification does not edit active-release.json. An operator explicitly activates the qualified version. Only future runs use it; old runs and reports remain linked to their original release.

What the Coding Agent is expected to build

The open-ended work is not “write a better prompt.” A useful candidate contains coordinated artifacts on both sides of the contract:

ArtifactQuestion it answers
Authority map and rule cardsWhich passage defines the rule, scope, trigger, exception, priority, and intended result?
LongTextJS schemas and extraction profilesWhat neutral, anchored observations must be materialized from production documents?
CircuitJS modulesHow are those observations correlated, revised, searched, verified, and published?
Witness and verifier referencesWhat concrete evidence allows a trusted checker to accept the candidate?
Natural benchmark casesWhich positive, close-negative, exception, boundary, ambiguity, and coverage texts fix operational meaning?
Compatibility profile and limitationsFor which formats, languages, structures, producers, and evidence conditions is this theory qualified?

Worked repair: dialogue is not narration

Assume a run reports the phrase “de fapt” inside a line of dialogue, but the style rule applies only to narration. A reviewer rejects the finding and marks the disputed scope. The learning system should not add a document-specific exception.

  1. The issue is classified as a scope or observation-boundary failure, not a new normative rule.
  2. The smallest reproducer becomes a natural regression family: one narrative positive, one dash-prefixed dialogue negative, and one nearby boundary case.
  3. The candidate may change the structural producer, extraction profile, circuit scope policy, or their contract depending on where the trace shows the error. It states a falsifiable repair hypothesis.
  4. Existing cases must still pass. The new dialogue case must stop producing the finding. Qualification verifies that the contract still has a producer and that the candidate and benchmark stayed unchanged during the gate.
  5. After explicit activation, the original document may be rerun under the new release. The old incorrect run remains auditable rather than being rewritten.

The current editorial-demo release embodies this distinction through its paragraph scope and released dash-prefix convention. Its benchmark contains positive, negative, exception, boundary, scope, and adversarial families rather than only the successful phrase match.

What the gate proves today

The implemented gate validates manifests, circuits, operator and verifier links, verification dominance, compatibility profiles, observation-contract alignment, available agent benchmarks, byte stability, copied snapshot integrity, semantic diff, impact map, and release digests.

Current qualification limit. It does not yet generate mutated CircuitJS or LongTextJS programs and calculate a mutation score. It also does not execute differential implementations, shadow/canary traffic, or the complete ideal metric program. Natural cases stored in a mutations suite are valuable cases, but are not executed program mutation. The gate reports only checks it actually ran.

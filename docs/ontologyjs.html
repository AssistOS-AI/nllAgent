OntologyJS: executable vocabulary

OntologyJS gives materializers and circuits the same constructor identities and catches local category errors before execution.

const O = ontology('facility.operations@1', extendsOntology(core));

export const Person = O.entity('Person', requires(named));
export const Door = O.entity('Door', requires(named));
export const agent = O.role('agent', from(O.Event), to(Person), exactlyOne());
export const theme = O.role('theme', from(O.Event), to(Door), exactlyOne());
export const Open = O.event('Open', requires(agent), requires(theme));

export default O.seal();

Open(agent(ana), theme(gate)) returns a ground Term. Replacing ana with variable(Person, 'person') makes the same call return a typed Pattern. Neither result is a record with arbitrary fields.

What belongs in an ontology

Local type validation, cardinality, normalization, index hints, lexicalization, and definitional views belong here. A behavior receives one local value. If a computation needs source evidence, a store query, a world, an exception, priority, or authority, it belongs in CircuitJS.

Identity

Source entities and anchored events use explicit identifiers; derived immutable values use structural identity. The experiment that selected this hybrid is explained in Architecture experiments.

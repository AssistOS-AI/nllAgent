The plan is the product; prose realization is optional

From a high-level idea to a CNL generation plan

Give nllAgent an idea and a published domain release. LongTextJS makes the idea addressable. Planning circuits apply the published theory and emit a concrete, ordered CNL specification for the document that should be written. A person or model can realize that plan later.

CNL is not the rulebook in natural language. Rules remain in CircuitJS. The CNL artifact is produced after those rules are applied to one idea. It says what this particular document should contain, in what order, and with what realization guidance.

The important boundary. CircuitJS produces CNL. The LLM consumes CNL only if final-text realization is requested.

What CNL/Plan-1 contains

The canonical CNLGenerationPlan contains the complete source idea, a document design, an ordered content plan, dependencies, concrete required content, realization guidance, release and circuit provenance, applied rule identifiers, a rule-to-plan verification witness, and limitations. Rule identifiers and witness locations explain how released theory shaped the plan; they are not natural-language constraint objects.

# CNL/Plan-1 generation specification

## Source idea
Write two English narrative paragraphs about Alice returning to an empty
railway station at dusk. End with one dialogue line from an employee.

## Document design
- Type: short literary scene in Markdown
- Language: English
- Audience: adult literary readers

## Content sequence
1. establish-scene
   Establish Alice, the empty station, dusk, and the restrained atmosphere.
2. develop-action
   Develop the action through concrete perception and movement.
3. close-scene
   End with the employee saying that the final train departed.

## Realization guidance
- Preserve every explicit fact from the source idea.
- Avoid “in fact” in narrative paragraphs.
- Use “perhaps” at most twice in one narrative paragraph.

## Plan verification
- ED-001: realizationGuidance:2
- ED-002: realizationGuidance:3

This plan is useful by itself: a reviewer can inspect it before prose exists, a workflow can store it as a specification, and different LLMs or writers can realize the same plan. The verifier rejects an applied rule with no valid contentPlan:<id>, realizationGuidance:<n>, or document:<field> location. It still does not claim that a later document passed audit.

What is reused, and what stays separate?

Reused domain knowledgeSeparate executable graph
Rule identities and authority anchorsValidation detects violations; planning selects and orders desired content.
LongTextJS schemas, entities, time, coverage, calendars, and unitsA planning circuit has purpose: planning and a plan output.
Registered deterministic and semantic operatorsA validation circuit retains purpose: validation and emits findings.
Compatibility profiles, benchmarks, release lineage, and provenanceThe optional realize–validate–revise loop is runtime orchestration, not validation logic.

Validation circuits do not embed CNL constraints, and the CLI has no embedded or hybrid mode. Learning agents may compile both graph families from the same rule cards, while manual publication checks them as explicit artifacts. A reusable bidirectional domain operator may be called by both.

Literary planning

An editorial release may know focalization, continuity, dialogue scope, chronology, weak constructions, and project style. Given a scene idea, its planning circuit can create steps for setup, point-of-view establishment, causal action, continuity-sensitive object transitions, disclosure timing, and closure. The CNL guidance incorporates the consequences of applicable style rules. The LLM is not expected to recover an entire style guide from a long prompt, and distant rules are not left “in the middle” of a context window.

Legal and normative planning

A normative release may encode identified laws, regulations, contracts, authority priority, definitions, obligations, deadlines, exceptions, and evidence policies. Given “prepare the notification for incident 17,” planning circuits can produce an ordered specification for identity and jurisdiction, material facts, applicable timing, applicable exceptions, actions, evidence, attachments, and explicit unknowns. The law stays in CircuitJS; the CNL plan describes the document for this incident.

If realization is requested, the resulting notice is validated again. nllAgent can therefore catch a wrong date, unsupported assertion, missing evidence statement, or misapplied exception. The guarantee is limited to the published release and available evidence; it is not universal legal advice.

Technical and scientific planning

The same path can plan specifications, procedures, protocols, and reports. LongTextJS can materialize components, quantities, units, versions, claims, datasets, and prerequisites. Planning circuits turn those into ordered sections and procedure steps. Optional realization writes prose around the plan; validation circuits then recheck terminology, units, dependencies, claim scope, and evidence.

Run the included plan-only example

node bin/nllagent.mjs plan \
  --agent editorial-demo \
  --release 0.1.0 \
  --foundation core \
  --input data/editorial-demo/examples/planning/idea.md \
  --output /tmp/editorial-plan.cnl.md \
  --translator none

No realization backend is needed. The command emits planned and stores the plan and its trace under planning-runs/. core is the default and is shown so the execution inputs remain visible; use --foundation off for a deliberately different world model.

Optionally realize and validate the plan

node bin/nllagent.mjs plan \
  --agent editorial-demo \
  --input data/editorial-demo/examples/planning/idea.md \
  --output /tmp/editorial-plan.cnl.md \
  --foundation core \
  --realize-output /tmp/editorial-draft.md \
  --max-revisions 2 \
  --translator auto

The backend receives only the CNL plan and a schema-bound output contract through role realization. The candidate is untrusted Markdown. Ordinary validation circuits and the selected foundation inspect it. Findings may drive role revision until the budget ends. Another application can omit these flags and realize the CNL externally.

What is and is not guaranteed

  • The CNL verifier checks structure, exact source-idea binding, source digest, observation provenance, document design, ordering, guidance, authority provenance, and concrete rule-to-plan coverage.
  • It does not certify literary quality, legal correctness beyond the release, or a future realization.
  • Optional realization is never accepted because a model says it followed the plan; validation circuits decide.
  • Plan-only execution remains valuable when no LLM is available or policy forbids model calls.
  • The current pre-publication checks cover the planning mechanism, not empirical live-model prose quality.

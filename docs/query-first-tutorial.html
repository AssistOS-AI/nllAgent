Author intent first · ordinary graph underneath

Write a relational rule without hand-wiring its graph

This tutorial is for circuit authors. It shows the restricted DSL they write, the checks the compiler performs, and the behavior a reviewer can expect. Generated execution plans belong in the query-first reference because they are compiler artifacts, not the author interface.

Experimental, bounded profile. The implementation supports typed scans, filters, projections, deterministic order, inner/semi/exact anti-join, three-valued expressions, and collect, unique, and priority tables. Aggregates, ordered patterns, arbitrary callbacks, and native indexes are not implemented.

1. Start from a reviewable verbal rule

For every extracted paragraph, flag the whole word “TODO.” Match without case sensitivity. Keep the source paragraph as evidence and verify the result against its exact anchor.

A direct three-node operator wrapper is still simpler for this isolated lexical rule. We use it here only because the result is easy to inspect; query-first becomes valuable when several rows share the same document domain, joins, status policy, or precedence.

2. Author one query and one decision table

export default queryFirstCircuit({
  kind: 'CircuitJSQueryFirst',
  dialect: 'circuitjs-query-first@1',
  id: 'editorial.query-first-phrase',
  version: '1.0.0',
  sourceRuleReferences: ['authority/style-guide.md#qf-001'],

  queries: {
    paragraphs: {
      kind: 'LongTextQuery',
      schemaVersion: 1,
      id: 'q:paragraphs',
      from: {
        relation: 'observations',
        as: 'p',
        type: 'document.paragraph@1',
        statuses: ['extracted']
      },
      where: {
        op: 'eq',
        left: { field: 'p.payload.structuralRole' },
        right: { literal: 'paragraph' }
      },
      select: {
        paragraph: { ref: 'p' },
        text: { field: 'p.payload.text' },
        order: { field: 'p.payload.order' }
      },
      orderBy: [
        { expr: { field: 'p.payload.order' }, direction: 'asc' },
        { expr: { field: 'p.id' }, direction: 'asc' }
      ],
      budgets: { rowsRead: 100, intermediateRows: 100 }
    }
  },

  decisionTables: [{
    kind: 'DecisionTable',
    schemaVersion: 1,
    id: 'table:phrases',
    input: 'q:paragraphs',
    hitPolicy: 'collect',
    unknownPolicy: 'report-undetermined',
    verifyWith: 'query.decision-replay@1',
    rows: [{
      id: 'QF-001',
      priority: 10,
      authority: ['authority/style-guide.md#qf-001'],
      when: {
        op: 'wholeWord',
        left: { field: 'p.payload.text' },
        right: { literal: 'TODO' },
        caseSensitive: false,
        locale: 'und'
      },
      then: {
        rule: 'QF-001',
        verdict: 'violation',
        severity: 'warning',
        subject: { field: 'p.id' },
        scope: { field: 'p.scope' },
        mainAnchor: { anchorFrom: 'p' },
        explanation: 'The paragraph contains an unresolved TODO marker.',
        remediation: 'Resolve the task and remove the marker.'
      }
    }]
  }],

  budgets: { nodes: 20, wallTimeMs: 5000 }
});

The verbosity is concentrated where a reviewer needs it: exact observation type and status, field paths, ordering, authority, hit policy, unknown policy, candidate shape, and verifier. Node identifiers and wiring are generated.

3. Let compilation reject structural mistakes

The loader first proves that the file is one restricted constructor with plain data only. The query compiler then resolves bindings and fields, checks scalar types, requires total order where needed, derives row and intermediate budgets, checks table policy, creates a QueryContract, and selects exact registered runtime implementations. A typo such as p.payload.texxt fails before publication.

Author intent lowers to the existing safe path. The generated source map preserves query, table, row, and authority identities. Physical node names may change; those logical identities remain the explanation boundary.

4. Follow one match and one close negative

For “TODO: cite the source,” the query selects one paragraph and keeps dependencies on its observation and anchor. Row QF-001 evaluates TRUE, constructs a candidate, and asks the replay verifier to rerun the query, condition, candidate template, dependencies, and anchor. An accepted record reaches emit.

For “The todolist is complete,” the whole-word condition is FALSE, so no candidate exists. If a required field is unavailable, the condition is UNKNOWN, not false. The table records an undetermined decision or blocks according to unknownPolicy.

5. Treat absence as a coverage question

An anti-join may construct “no matching row exists” only when it names a verified closed-world coverage domain for the exact source revision, type, scope, channel, producer, method, exclusions, and accepted statuses. If the source contains no match but coverage is open or failed, the query returns UNKNOWN. A row limit is a computational bound and can never prove absence.

File order never acts as hidden precedence.

7. Use the smallest correct form

Prefer an exact operator wrapper when a reviewed algorithm already exists. Prefer query-first when the rule is naturally a typed selection, join, or decision family. Keep a direct graph or registered operator for state, recursion, solvers, search, complex temporal reasoning, or anything the bounded profile rejects. Compact syntax is not a reason to conceal a mathematical algorithm.

A query row cannot contain a JavaScript callback. If a query prepares data for a custom algorithm, use a direct CircuitJS node backed by a trusted runtime extension. The current experimental profile has no generic operatorRule form.

8. Know what publication proves

Tests run the author query/table evaluator and the generated graph, then compare query results, decision records, and verified candidates. Published experimental releases retain the normalized author value, generated graph, QueryContract, source map, digests, and differential result in query-first-artifacts.json. This proves equivalence for the implemented path and tested cases; it does not imply a native optimizer exists.

Documentation / Domain packages

A small shared foundation, explicit domain meaning

Editorial, normative, and technical theories

nllAgent shares a bounded foundation for explicit state, time, exact arithmetic, elementary quantities, types, and literal emotions. Everything richer comes from a published domain package of observations, rules, operators, verifiers, examples, compatibility limits, and explanations. This page explains that extension boundary; it is not a catalogue of every possible ontology.

How the platform generalizes

A universal set of fields such as Entity, Fact, and Constraint looks simple until all meaningful semantics move into opaque payloads and prompts. nllAgent keeps a smaller common kernel: sources, anchors, versioned types, scope, time, alternatives, epistemic status, provenance, coverage, observation bindings, budgets, witnesses, and publication rules. Domains extend the nominal vocabularies and compose the reasoning regimes they actually need.

This design resembles a platform with specialized theories rather than one giant classifier. The same scheduler can coordinate lexical matching, state timelines, deadlines, constraints, graph search, or model judgments because every component declares typed inputs, effects, limits, and verification. It does not imply that any operator understands arbitrary natural language.

What is shared by default? foundation-core@1.1.0 recognizes the six documented assertion families and applies five bounded circuits. It supplies no diagnosis, rich physics, unrestricted natural-language ontology, or current political, geographic, social, economic, or legal facts. See Default foundation.

A domain is a linked package. Authority determines both what the document compiler must observe and how the theory may judge. Natural cases and compatibility probes prove that both sides use the same operational meaning.

Editorial domain: from exact phrases to continuity

An editorial linter combines rules with very different guarantee levels. The included editorial-demo is the implemented starting point. Its deterministic Markdown observations support two exact lexical rules: a weak phrase in narrative paragraphs and a per-paragraph frequency limit. Circuits exclude dash-prefixed dialogue and fenced code, respect whole-word boundaries and exact thresholds, preserve Unicode source spans, and use replay verifiers.

A richer editorial package can add semantic observation types such as Scene, Focalizer, DiscourseMode, MentalStateAttribution, ObjectEvent, NarrativeTime, and KnowledgeState. These remain LongTextJS interpretations. CircuitJS derives concepts such as unauthorized mind access, use without possession, temporal regression, or premature revelation.

Example: focalization

  1. The rulebook defines third-person limited narration, direct mental access, licensed inference, dialogue, free-indirect discourse, and declared scene transitions through examples and counterexamples.
  2. The extraction contract asks for scene boundaries, focalizer candidates, experiencer, attribution mode, discourse mode, and exact passages—without asking whether the rule is broken.
  3. The circuit groups observations by scene, resolves or preserves focalizer alternatives, selects direct mental attribution to another character, and applies licensed exceptions.
  4. A semantic rubric may still be needed to distinguish direct access from inference. The finding can have exact evidence and a verified rule path while remaining model-judgment or review-required.

Example: object continuity

The implemented narrative.object-continuity@1 operator tracks leave, retrieve, transfer, replace, and use events by stable identity. If a phone is left in a car and later used elsewhere, the verifier replays all materialized intervening events. A finding is possible only when the object identity, event order, transition policy, and coverage satisfy the release contract. Model-produced event semantics keep an evidence-assisted ceiling.

Normative domain: obligation, exception, and incomplete evidence

A policy linter must keep rule authority separate from case evidence. Its observation vocabulary may include incident, confirmation event, responsible actor, notification event, official channel, outage, timestamp, jurisdiction, rule version, and record completeness. Its theory derives obligation activation, deadline, exception application, satisfaction, non-compliance, not-applicable, undetermined, or policy conflict.

Example: an incident notification deadline

  1. The authority package defines what counts as a critical incident and confirmation, who must notify, the elapsed duration, the official channel, the outage policy, and source precedence.
  2. LongTextJS materializes incident and evidence observations from the concrete case, retaining exact timestamps, timezone, source authority, and open- or closed-world coverage.
  3. CircuitJS instantiates the obligation, invokes temporal.deadline@1, applies the named outage rule, searches qualifying notification events, and carries the coverage contract into its witness.
  4. The verifier recomputes the deadline and action relation. Missing action can support non-compliance only when the relevant official record is complete. Selected emails produce undetermined or a limited “not identified in supplied material” statement.

Technical and scientific domain: typed claims and solver-backed checks

Technical packages may define Definition, Quantity, Unit, Component, Requirement, ProcedureStep, Measurement, Claim, Evidence, Dataset, Version, and ApplicabilityCondition. The source wording remains anchored; normalized values and derived conflicts retain their conversion or dependency witnesses.

Examples of executable checks

  • Numerical consistency: units.convert@1 normalizes supported length, pressure, mass, and temperature quantities; constraints.interval-conflicts@1 compares requirements only after component identity, qualifier, conditions, scope, and version align.
  • Procedure conformance: state.timeline@1 applies ordered preconditions, effects, inertia, and explicit retraction to detect missing or impossible steps.
  • Rule closure: logic.fixpoint@1 computes finite positive consequences with proof provenance.
  • Competing evidence: argumentation.grounded@1 preserves explicit attacks and computes a named acceptance semantics rather than hiding conflict.
  • Graph tasks: graph.shortest-path@1 produces a path witness and separate optimality check, demonstrating how a textual problem can route to a specialized solver.

Scientific claim/evidence review can identify a mismatch between population, method, result, and conclusion or flag causal language unsupported by the declared design. The runtime may certify unit conversions, formula replay, or an explicit graph property. It does not claim to certify arbitrary scientific truth or to turn a model-extracted causal interpretation into a theorem.

Compatibility must be proven before reuse

Similar names are not sufficient. A narrative scene is not automatically a dramatic scene; an informal message is not automatically an official notification; an experiment is not automatically a simulation run. An adapter must state its preconditions, field mapping, lost information, coverage effect, and maximum guarantee. Publication checks need natural positive, negative, ambiguous, and coverage cases demonstrating the shared operational meaning.

When a new document cannot satisfy the package, preflight should stop the dependent circuits and create a learning need. Expanding the compatibility profile is a release change with new benchmarks, not a prompt tweak during the run.

Build a new specialized agent

  1. Create a named agent and fix its intended use, users, authority order, document population, output classes, and automation limit.
  2. Collect representative rulebooks, calibration documents, reviewer decisions, formats, languages, and operational context. Record missing regions before claiming compatibility.
  3. Mine natural positive, close-negative, exception, boundary, ambiguity, coverage, adversarial, and long-range cases.
  4. Design the smallest LongTextJS observation vocabulary that makes the rules executable. Separate mention from identity and source observation from rule-derived concepts.
  5. Choose CircuitJS patterns—relational, state, temporal, fixpoint, argumentation, search, solver, or rubric—and design each witness before implementation.
  6. Use existing trusted operators where their semantics fit. Propose a reviewed operator and verifier when they do not; never hide new execution in unrestricted circuit code.
  7. Declare supported language, format, structure, auxiliary registries, coverage policy, cost, and known limits in the compatibility profile.
  8. Build a candidate with the learning workflow, run natural benchmarks, inspect its limitations, and then publish it explicitly when it is ready.
Implemented core versus extension contract. The repository currently ships Markdown ingestion, lexical editorial examples, semantic observation translation, a continuity operator, and several deterministic reasoning operators. Rich legal, scientific, multilingual, multimodal, external-solver, causal, and formal-proof packages are supported by the extension architecture but are not all bundled as published production agents. Unsupported evidence remains a compatibility gap.

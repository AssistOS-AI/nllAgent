The document side

LongTextJS is a program of this source

LongTextJS turns one immutable document revision into an addressable world that CircuitJS can consume. It preserves what the source says, how interpretations were produced, and what remains unknown. This is the data-model reference; start with the Quick Tutorial if you only need to author or run a circuit.

What is compiled

For the current production path, the input is Markdown. The compiler does not reduce it to a summary or an embedding. It preserves canonical text, structure, global Unicode positions, block identities, channels, and exact quotations. It then adds typed observations required by the selected release.

flowchart LR
  STRUCT[Markdown source + exact anchors] --> OBS[Structural observations]
  OBS --> SEM[Selected foundation + demanded domain observations]
  SEM --> LIMIT[Coverage + capabilities + gaps]
  LIMIT --> LTX[Canonical LongTextJS JSON]

Compilation adds meaning without replacing source. Deterministic structure comes first. The versioned foundation recognizes a small controlled subset; release producers add only demanded domain interpretations. Coverage and gaps travel with the program.

Why it is called LongTextJS when the artifact is JSON

LongTextJS is a declarative data language. Its canonical current dialect is longtextjs-json@1, and the persisted run artifact is JSON-compatible plain data. The compiler and runtime are JavaScript modules, but a document program contains no imports, callbacks, loops, classes, ambient I/O, or executable source. “Program” means that the runtime can interpret its typed relations, dependencies, task, coverage, and gaps—not that the JSON evaluates itself.

This differs intentionally from CircuitJS authoring. A maintainer may use one restricted export default circuit({...}) expression as convenient source syntax for reusable theory; the loader immediately normalizes it to canonical plain data. LongTextJS instances are generated by ingestion and approved materializers from one source revision. An optional future authoring frontend would still have to produce exactly the same canonical data and could not add runtime authority.

The shape emitted today

A normal program contains one source package, view:whole, the run task, blocks and anchors, structural scopes, ontology-pack selection, observations, capabilities, coverage records, gaps, and diagnostics. The extensible ontology and the default boundary

LongTextJS has a shared upper ontology, but not one universal semantic reading of every document. The common layer standardizes source objects, blocks, anchors, views, scopes, mentions, entity hypotheses, identity links, typed observations, worlds, time-bearing values, status, provenance, alternatives, coverage, and gaps. Domain packages extend it with versioned schemas for the concepts they can actually define and test.

LayerProduced by default?Examples and epistemic meaning
Source and Markdown structureYes, deterministicallyHeadings, paragraphs, heuristic sentences that preserve decimal points between digits, lines, exact anchors, order, view, structural scope, capabilities, and closed structural coverage. These are extracted.
Foundation assertionsYes, unless --foundation offControlled-English entity, state, type, explicit before, exact arithmetic, quantity, and literal emotion records. Coverage is open-world and every record describes a source claim, not outside-world truth or a diagnosis.
Resolved entities and identity linksNo generic population todayThe canonical relations exist in every program but the Markdown baseline initializes them empty. A domain identity producer must preserve anchored mentions, alternatives, scope, world, and evidence instead of merging equal names.
Richer events, actions, relations, discourse, and emotionsOnly on circuit-derived demandAn approved release profile defines an exact nominal type and payload. A model-assisted interpretation is anchored and normally admitted as proposed with alternatives and open-world coverage.
Violation or complianceNever as default extractionThis is reusable rulebook judgment. CircuitJS constructs a candidate and an independent verifier controls publication.

For example, a continuity release may demand narrative.object-event@1 and ask for actor, object, action, polarity, modality, order, and exact evidence. An affect-analysis release may define a separate emotional interpretation schema. A lexical cue can be located mechanically, but an emotional interpretation still needs context, a schema, a producer, alternatives, and a guarantee appropriate to proposed evidence.

Complete program data dictionary

LongTextJS has no hidden execution primitive: each construction is a finite record, array, or id-keyed map. The algorithms that create them live in ingestion and approved materializers. This table names every canonical top-level construction, its data structure, and the claim it may carry.

ConstructionShape and identityMeaning and producer algorithm
kind, dialect, idScalar discriminators and stable program id.Select the LongTextProgram schema and canonical dialect; they do not identify truth or coverage.
sourceOne record keyed by source id and immutable revision digest.The adapter canonicalizes bytes, media type, language, line endings, channels, structure, and text. It is the lexical authority.
blocksOrdered array of stable block ids with kind, text, anchor, structural path, and source order.The Markdown parser segments headings, paragraphs, lists, quotes, code blocks, thematic breaks, and blank boundaries. Block order is explicit.
anchorsId-keyed map of source revision, half-open code-point range, exact quote, block, structural path, bounded context, and digest.Anchor construction rereads canonical text at the declared range. It locates evidence but does not assign semantic meaning.
schemasArray of exact nominal schema identifiers.Declares available program and payload vocabularies; a name alone does not prove producer capability.
ontologyPacksArray of immutable pack selections and descriptors, including versioned principles, observation types, vocabularies, and limitations.Records whether foundation-core or off shaped materialization. Selection itself is not source evidence.
viewsArray of view ids with source, scope, members, completeness, selection, and deterministic order.A view selects canonical objects without synthesizing source and is reconstructible from its selection.
scopesArray of scope ids with kind, source, and explicit relationships.Represents document, scene, temporal, jurisdictional, experimental, or hypothetical boundaries.
worldsArray of world ids, assumptions, and exclusion relationships.Separates coherent alternative interpretations; mutually exclusive worlds are never unioned silently.
mentionsFinite array of anchored local mention records; empty in the current deterministic Markdown baseline.Preserves occurrences before identity resolution; equal text does not imply one entity.
entitiesFinite array of scoped entity hypotheses and supporting mention ids; empty until an approved producer populates it.Represents identity under one producer and world, not universal identity.
identityCandidatesFinite array of same/distinct candidate links, evidence, scope, status, and world; empty in the baseline compiler.The identity service preserves unresolved alternatives and supporting evidence.
observationsFinite array with id, exact type, payload, scope, anchors or external provenance, status, producer, support, alternatives, and confidence.Structural parsing, deterministic extractors, or schema-bound model materializers create descriptive facts. A rule-dependent verdict belongs in CircuitJS.
taskOne record for goal, source/view scope, release selection, absence policy, budgets, desired guarantee, review policy, and output.Constrains what this program may be used to decide. It is operational context, not rule authority.
capabilitiesFinite array of type, producer, attainable status, coverage mode, and operational support.Describes what approved producers can attempt; it cannot substitute for observations or coverage.
coverageFinite array of exact source revision, view/scope, channels, types, producer, method, mode, exclusions, failures, and verification.Certifies one bounded materialization domain. Absence must consume a matching closed-world token.
gapsFinite array of missing type, scope, producer attempt, reason, criticality, and recovery metadata.Records unavailable or failed materialization. A gap is neither false nor a negative observation.
diagnosticsFinite array of stable structured source or compilation notices.Reports malformed, suspicious, lossy, or bounded behavior; compatibility decides whether it blocks.

A queryable world, not a database claim

These constructions can be mounted as read-only logical relations. Singular source and task become one-row relations; the anchor map is enumerated by stable id; arrays retain only their declared semantic order. A query result is derived data with references back to canonical ids. Type/status, anchor, scope, source-order, and coverage indexes may accelerate repeated access, but they are disposable caches and never evidence.

Experimental execution. Query-first authoring now exposes every canonical construction through a deterministic reference adapter. Observation scans also become generated CircuitJS observation bindings, so the existing producer, status, and compatibility gate remains active. Benchmark execution compares direct query/table evaluation with the lowered graph. Native indexes are not implemented.

Source, anchor, observation

ObjectWhat it assertsWhat it does not assert
Source packageThese are the canonical bytes/text, revision, language, structure, and channels analyzed.That any interpretation of the text is correct.
AnchorThis exact quote occupies this half-open Unicode code-point range in this block and revision.That the quote has a particular semantic role.
ObservationA named producer interpreted or extracted this anchored source as a nominal versioned type.That a rule has been satisfied or violated.

This separation is why an invented model quotation cannot become evidence. Model output names an exact quote inside one source block. The materializer locates that quote again, computes the global anchor, validates the payload, and only then inserts a proposed observation. Repeated equal quotations are assigned to successive occurrences rather than collapsed onto the first match.

Status preserves how something became known

A deterministic paragraph observation is extracted. A model-identified object event is normally proposed. A search branch may add an assumed object. A circuit consequence is derived. A checker may mark one exact property certified. Human confirmation has its own status. Confidence can rank alternatives, but cannot silently change any of these categories.

This matters downstream. A deterministic state replay over model-proposed events can verify that the replay follows the released transition policy; it cannot retroactively prove that each event was semantically classified with mechanical certainty.

LongTextJS is selective, not total

The runtime compiles structure and the selected foundation, then loads the release’s circuits. Output-reachable observation bindings determine the additional domain observation types to materialize. A lexical circuit may need only document.paragraph@1. A continuity circuit may additionally need object events, identity, order, modality, and an intervening-scope search. nllAgent does not attempt to formalize every possible fact in every document.

No unrestricted built-in profile runs merely because a sentence contains a person-like name or verb. The foundation is limited to its documented forms. Rich semantic requests go through extraction profiles listed by the selected release and the backend-neutral translation gateway, and a profile runs only when an output-reachable circuit demands its exact outputType. Configured AchillesAgentLib is preferred; the current Coding Agent reference adapter is the fallback. Both return schema-bound candidates to the same materializer. Neither backend constructs the source package, changes anchors, declares coverage unilaterally, or edits CircuitJS. See Compilation and translation.

Coverage and gaps are part of the program

Coverage records name the source revision, channel, scope, observation types, producer, method, exclusions, failures, and completeness mode. A complete structural scan can support “the phrase does not occur in any narrative paragraph in this view.” Top-k semantic retrieval cannot support “no notification exists anywhere.”

A gap is not a negative observation. It may identify an unavailable producer, invalid model output, unknown structure, unresolved identity, missing operational context, unsupported language, or insufficient materialization. The compatibility gate consumes these records before CircuitJS is allowed to make a claim that depends on them.
